# 桌边规则系统：现状与迁移

## 当前内容

- 原书层：`/books/` 保留 PHB、DMG、MM 及已导入译稿的章节、表格、原顺序与永久链接。
- 资料层：`/spells/`、`/monsters/`、`/equipment/`、`/classes/`、`/races/` 有结构化数据和筛选；随机表在 `/tables/`。
- 工具层：`/character/` 是 REF2 风格双面人物记录，可本地保存、导入／导出、打印。
- 问题：原首页以资料分类为主；`/combat/` 与 `/adventure/` 多为碎链接；车卡规则判断散在页面脚本；原书、速查和工具之间缺少以游戏情形为中心的入口。

## 信息架构

| 层 | 路径 | 职责 |
|---|---|---|
| 游戏情形 | `/play/` | 角色创建、旅行、遭遇、战斗、休整、升级、施法时的执行顺序 |
| 规则专题 | `/rules/` | 中等粒度的跨书说明；使用页内锚点而非再拆碎 |
| 资料对象 | 保留 `/spells/` 等现有路径 | 法术、怪物、装备、职业、种族等永久对象 |
| 工具 | `/character/`、`/dm/` | REF2 人物记录与主持工具 |
| 原书 | 保留 `/books/` | 逐章译文和出处 |

现有资料对象与原书路径不迁移，避免破坏群聊中已经分享的链接。新增的 `/play/` 和专题页指向现有条目；旧的原子规则页可继续存在，但导航和搜索优先指向专题锚点。`/reference/` 与 `/book/` 不另复制同一内容。

## 数据与规则引擎

沿用现有 `SourceReference`、Zod 条目和本地译稿；不在组件里复制规则正文。人物卡的判定函数放在 `src/rules-engine/`，返回结构化的值、原因、出处。第一批实现：职业／种族／属性资格、基础护甲等级、负重与移动。后续按经过原表核对的顺序接入攻击矩阵、豁免、升级和法术位；没有可靠表格时不自动给出看似精确的结果。

## REF2 人物卡迁移

保持正反面、字段名称、保存格式和打印布局。先增加关联选择与可解释计算；用户已经填写的自由文本仍能导入。自动值只写入未被手动覆盖的字段。校验采用双向更新：改种族、职业、属性或装备都会重新给出冲突原因，但不清除既有选择。DM 裁定由单独的覆盖开关保留，不改变原始规则判断。

## 实施顺序

1. 首页改为“游戏中／查资料／工具／规则书”，居中保持窄栏。
2. 先完成战斗专题及情形页，再处理旅行、遭遇、角色创建与施法。
3. 车卡调用独立规则引擎，并让装备和 AC 具有可解释结果。
4. 搜索提高情形与专题的优先级；DM 工具复用现有随机表，不制造空页面。
5. 每批以本地译稿和构建后页面核对来源、链接与实际使用场景。
