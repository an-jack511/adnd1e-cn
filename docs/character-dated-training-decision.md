# H04：带日期的训练授级与旧课程时间对账

日期：2026-10-16。来源为已核 DMG 印刷 86 / PDF 87 的训练游戏时间要求，以及 DMG 印刷 37 / PDF 38 的战役时间/活动/位置记录。沿用共享及前轮原页证据，不宣称本轮重新阅读了 PDF；来源标识为 `dmg:86:gaining-levels`、`dmg:37:time-in-campaign`。

## 问题和决策

H04 指出现有运营行动允许在没有日历的情况下记分数周训练，然后直接授级，无法回答这周占用的实际游戏日期和地点。勾选连续性不是完整时间事实。

新写入只允许 `scheduled-training-segment` 增加训练进度。旧 `training-segment`、`award-level` 保持历史重放语义，但在 `commitCoreCampaignAction` 新操作入口拒绝。新授级命令为 `award-level-dated`，必须明确填写游戏授级分钟，且不得早于当前课程所有片段的完成时点。

`inspectCoreDatedTrainingCourse` 检查日历单位、每一已记录进度片段的唯一对应活动、角色 ID、training 类型、非空地点、合法整数时间、原有分数周换算后的完整分钟数、两个规则来源及片段首尾相接。提前结束的活动不再能证明原完整进度。仍由原成长流程检查实际课程完成、付款、HP 骰和其他门槛，不能仅有日历就授级。

新 `datedLevelAwards` 投影记录授级行动、DM 标签、实际授级分钟、目标等级、课程起止及活动引用，声明验证范围 `course-interval-coverage`。不把它扩张成所有世界活动兼容性、旅行合法性或高级别职位条件已自动认证。

## 兼容与对账

旧档没有凭空新增日历、授级时点或派生认证字段；既有历史行动仍按原序列重放。`replayCoreCampaignActions` 是纯历史重建接口，不是当前新操作写入口，也不证明行动年代或真实 DM 身份。当前静态 JSON 信任模型没有签名认证，不能用“导入成功”表示所有旧行动均符合现行完整规则。

对于仍在进行或已完成训练但尚未授级的旧课程，新增 `reconcile-training-segment`：只能引用当前课程已有片段，按其原分数周建立游戏起止、地点和来源；须记录 DM 的实际历史依据。它不增加片段进度、不更改 XP/等级/HP、不收费或退款。重复安置、未知片段、时间/地点非法或已有冲突会拒绝。完成全部对账后才可走新的带日期授级。

已经授级或已经严重中断的旧课程不在此对账入口范围内，仍保全并提示旧式记录，不自动认定时间完整。完整已结算历史迁移/修复仍是待办。不能抹掉既往等级来绕过兼容性问题。

## UI

训练区显示当前课程时间覆盖情况；缺少日历占用时停用授级，提供旧进度片段选择、实际历史理由，以及复用上方日期/地点输入的对账操作。完整时显示课程结束的战役日/日内分钟，要求另填实际授级时点。不存在按现实日期推算、自动补一周或自动补授级日期。

## 验证及限制

专项测试覆盖无日历、缺失/重复活动、错误角色/类型/地点、来源缺失、错误/非法时长、时间断缝及提前结束，确认失败不修改原件。生命周期新增合成兼容夹具：历史重放建立两段未安置旧进度，可原样读回；新旧式授级被拒绝，新带日期授级在无日历/缺片段时拒绝；对账后进度仍两段、付款仍一次、钱包不再扣款，随后可完成带日期授级并重放。

另验证已授级旧历史仍能原样读回、没有编造日历；新建课程不能新提交旧式授级，授级早于课程结束一分钟会拒绝。既有多门槛、重训、普通三级/四级分支改用真实课程结束时点。全部都不是旧档由真实历史软件生成的证言，而是明确的合成兼容/集成测试。

H05 重叠活动如何失效训练/休养、H06 跨地点位移及人物时间线仍待处理；当前覆盖检查不冒称已经解决。纯工作流训练数学单测不经过运营写入口，不能用其“通过”认证现实战役时间覆盖。新界面尚需浏览器路径验收。
