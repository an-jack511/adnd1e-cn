# 产品、界面与迁移规格

## 1. 审计结论

源码快照：2026-10-16，工作树含本任务与用户的未提交修改。没有重置、批量格式化或改写用户的全站布局、书籍页面与译稿。原型使用独立页面壳和作用域样式。

| 当前入口／组件 | 已有能力 | 确定缺口／风险 | 目标去向 |
| --- | --- | --- | --- |
| `/character/` | 旧手工表、打印、localStorage多个角色、参考计算 | 页面自己承认未接新版事件；可直接编辑等级/HP/法术文本，不能据此认证。与正式运营保存不相同 | 旧档只读查看／迁移入口；切换完成后不作默认主页 |
| `/character/create/` | DMG I–IV、原骰、分配、草稿 | 只完成属性，用户须换页/换文件继续 | 创建向导第2步；保留算法 |
| `/character/create/core/` | 资格、任务、初始资源、进度 | 下游选择整体失效，身份重选与已恢复锁定难理解；任务事实偏开发者界面 | 创建任务图和影响预览 |
| `/character/review/` | DM任务批准、准入导出 | 普通玩家暴露审核及原始字段；不能作日常卡 | 需要时进入的高级DM层 |
| `/character/archive/` | 校验创建准入档 | 是一级创世事实，不等于当前运营状态；JSON不是人物卡 | 人物卡“创建依据” |
| `/character/operations/` | XP、训练、钱包、物资、法术消耗、生命及日历 | 大表单把高频生命操作放在训练之后，要求事件ID/时间分数/内部来源。没有游戏模式 | 分拆为人物卡、成长、时间线；复用同一runtime |
| campaign/import/capabilities/abilities | 配置、隔离、能力与表格 | 入口数量对应技术模块而非玩家任务 | 设置、全局打开、上下文资料 |
| campaign IndexedDB | 原子CAS、旧件、损坏保全 | 导入续接与恢复分支界面未闭合；无统一自动保存；浏览器会丢数据 | 单角色仓储门面，保留已有事务 |

现站 URL 的网页检索器请求失败，不能从这个结果推断网站下线；本轮UI观察以本地源码及实际本地浏览器为准。前次线上版本与当前脏工作树不是同一快照。

审查还发现：runtime 读取行动数上限与追加输出上限可能不对称，长档案每步嵌入完整快照会放大体积；当前没有通用安全历史纠错。它们是后续生产集成P0门槛，不在本轮顺手改写引擎。详见DM评审，具体满额性能与失败仍待实验。

## 2. 四个玩家页面

生产目标路径为 `/character/create/`、`/character/sheet/`、`/character/growth/`、`/character/journal/`。本轮地址为 `/character/prototype/#create|sheet|growth|journal`，四视图同内存状态；不是正式路由切换，也不承诺URL携带档案。

### 创建

任务阶段：战役采用 → 生成/录入原骰 → 分配 → 资格 → 人物特征及职业专属事项 → HP/钱币/采购/初始授予 → 审核。阶段导航始终显示当前步骤、阻塞原因和下一任务。职业差异来自任务工厂，不是同一张表换标题。

依赖图：规则配置影响所有适用规则；原骰/分配影响资格、属性调整、HP、语言及法术理解；身份影响职业装备、熟练、施法与特殊能力；起始金钱只使采购待重新核算。修改前显示受影响事项；未受影响的事实保留。随机结果不得因rerender/预览/返回自动重掷。已准入档不倒回创建编辑，必须纠错或另建人物。

原型固定人类单职业MU、男性、TN，只开放原骰方法/分配、姓名、HP和资金骰。显示未接通的年龄、语言、熟练、灵能及真实法术准备；生成的是演示卡，不是完整合法人物。

### 我的角色

顶部身份+HP/AC/已获等级/XP，生命快捷操作。游戏模式优先高频行为；完整模式显示基础/修正/当前值及依据。标签：冒险战斗、属性能力、法术、装备财富、人物资料、随从资产。基础矩阵与最终修正分开，不能THAC0线性生成重复20。

法术按“理解资格→实际书内条目→准备副本→消耗→恢复活动”组织；神术不用Chance to Know。装备显示实例、数量、位置和实际价格；钱币面额与价值都保留；未知重量不当零。当前/最大/永久/临时/覆盖须有文字标签。

### 成长

左/上方资格概览 → 当前课程任务 → 前后差异预览。XP已达、评价待定、导师待确认、资金不足、时间未满、严重中断、职业挑战未完各是不同阻塞。一次提交只授一个等级；HP骰、新熟练、法术容量与特殊能力各有待办。不因升级送出免费准备或书内法术。

### 战役记录

战役时点、活动、时间线、详情。活动先提案，再计划/付款/实际开始/实际完成/结果；不是“时间已过即成功”。显示训练、研究、休养、旅途、雇佣、地产及资产关系。玩家只看公开事实；DM高级层另查看秘密依据。后补活动触发利益复查，不只检查日历是否重叠。

## 3. 视觉系统

| 令牌 | 值/要求 |
| --- | --- |
| 背景/正文/强调 | `#F8F6F0` / `#263448` / `#8B3530` |
| 金色/边线/次要文字 | `#B18B55` / `#D9D4C8` / `#626968`；金色不用作小字唯一前景 |
| 字体 | 中文标题宋体/衬线回退；正文微软雅黑/PingFang；数字少量Georgia。无需外部字体网络 |
| 结构 | 最大1440px；桌面216px固定导航、内容、按需230px说明；不依赖全站旧BaseLayout |
| 间距 | 4/8/12/16/20/24/32体系；正文14px、表格12–14px，标题27–32px |
| 边框与形状 | 1px线、2px控件圆角；不用大圆角卡片、渐变、玻璃或浮夸阴影 |
| 移动端 | ≤640px底部四项导航、44px操作、单栏、局部标签滚动；不把三栏直接压缩 |
| 中间宽度 | 900px以下说明栏移后；1180px以下创建摘要改后置；步骤窄屏横向可达 |

组件合同：导航有当前状态；标签按钮有按下状态；输入有label/边界；任务显示文字状态；预览列出差值及未自动处理部分；来源弹窗注明印刷/PDF页、核验范围和链接类型；错误在本任务和全局状态区可达；空态解释怎样开始；模态可Esc取消、焦点回入口。红色+文字用于错误，不靠颜色单独传达。

生产加载/保存状态统一为：未保存、保存中、已保存到本机、保存失败、冲突、只读保全。不能把“下载请求发出”写成“已备份”，也不能把浏览器保存当永久档案。打印显示事实/状态/来源，不带操作按钮；全分区打印仍待实现。

## 4. PL/DM生命周期合同

| 玩家操作 | 规则计算 | DM处理 | 文件变化 |
| --- | --- | --- | --- |
| 首次创建 | 原骰方法、分配、资格、初始资源和动态待办 | 允许方法/重掷、解释冲突、背景与法术取得 | 保存原骰与决策；通过后追加准入创世事件 |
| 进入战役 | 核对规则包版本/兼容/当前状态 | 接纳规则采用与例外；本地签名不认证 | campaign绑定与入场事件，不改历史骰面 |
| 受伤/治疗 | 生命、限制、HP变化，越界转专用流程 | 实际效果和来源；零HP、复活条件 | 实际资源变化及生命事件，限制独立 |
| 施法/物品使用 | 校验副本、数量及可用性 | 材料/目标/效果和不可确定部分 | 消耗指定副本或实例，不批量清空 |
| 冒险结算 | XP批次、钱币守恒、成长资格 | 评级、奖励、分配、实际战利品 | 分立经验/财富事实；不自动升等级 |
| 训练升级 | 阶段/时费/支付/连续日期/地点/冲突/职业门槛 | 导师、服务折抵、挑战、采用解释 | 独立付款课程与授级事件；原始HP骰 |
| 法术学习准备 | 理解轮次、书内条目、容量、休息学习时长 | 可得性、神授及例外；秘密分层 | 学习/取得/准备副本各自历史 |
| 研究制造休整 | 已明确的费用/资格/活动占用 | 可行性、配方、材料、秘密检查 | 提案到实际结果，不预写成功 |
| 获得随从/雇员 | 上限、薪酬与已知资源 | 招募、忠诚、士气、构成及据点 | 关系实例、角色链接、私密分层 |
| 永久变化 | 重算受影响资格/资源，保留原值 | 原因及既有效果追溯范围 | 永久事实事件与依赖复查，不覆盖出生事实 |
| 死亡/复活/退役 | 方法资格、体质/限制及状态 | 仪式/实际成功/不可自动事实 | 生死历次事件和保留终态，不删角色 |
| 保存分享迁移 | 格式、引用、重放、规则版本与差异 | 接续/分支选择、私档披露 | 原件保全，新件写入；公开摘要不可恢复私档 |

## 5. 分期与切换门槛

| 阶段 | 优先交付 | 进入下一阶段门槛 |
| --- | --- | --- |
| A 当前 | 审计、规则矩阵、四视图交互、候选schema、跨评审、设计验证 | 明示原型限制；桌面/手机真实走查；不声称全RAW |
| B P0 | 正式档案统一只读投影→人物卡、打开/自动保存/导出、日常Action适配、冲突比较 | 同一人物跨四视图、真实保存回读、损坏保全、不漏DM秘密；修复行动上限对称及体积风险 |
| C P0/P1 | 战士/MU/牧师/盗贼完整创建；后续其他核心职业 | 每职业一级到正式卡测试，全部必要事实完成，不用DM勾选填平算法缺口 |
| D P1 | 正式成长、训练、法术学习准备、日历、研究、关系与财富联动 | 三个真实非合成E2E、后补冲突/中断/纠错回归，多角色时点一致 |
| E P2 | UA/OA/生存包、多职/双职/Bard复杂路径与世界资产 | 各扩展分离版本/冲突策略；原页与矩阵格核验；全生命周期而非只有表数据 |

迁移顺序：先只读桥接旧入口→逐种预检与原件导出→显示字段映射及缺项→创建未准入候选→DM事实核对→在新分支验证运营→确认切换默认导航→旧页改重定向或明确只读工具。任何一步失败不删旧档、不静默双写；发布前保留旧静态版本可回退。新旧写入口不可长期同时写同一人物。
