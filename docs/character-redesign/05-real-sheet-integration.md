# Phase B 第一段：正式档案人物卡接入

日期：2026-10-17。此文追加在Phase A评审之后，不改写其当时“只有隔离原型”的历史结论。全目标仍未完成。

## 本轮真实实现

- `/character/sheet/` 新正式档案接入预览，读取既有单职业核心准入／运营格式，不接受prototype envelope冒充人物。
- `application/campaign-sheet.ts` 白名单公开view-model；姓名、职业、已获等级、XP、HP、库存、准备副本与有限活动摘要；不把完整模块JSON塞入玩家DOM。
- `actions/campaign-actions.ts` 稳定Action与纯预览，真实提交仍调用现有`commitCoreCampaignAction`。预览计划通过进程内WeakMap绑定原始输入和完整基线；伪造/过期计划拒绝，完全相同命令重试返回已提交结果。
- 当前动作：确认实际HP、记录伤害、正HP实际治疗、消耗库存单位、消费公开准备副本。零HP伤害进入既有生命状态机，不截到1。实际治疗不会解除恢复期，不假造治疗法术/消耗。
- 沿用同一IndexedDB数据库、槽、CAS和历史；从本地加载或首次明确保存后自动保存，保存中新增动作保留并接续保存。保存失败/冲突停止自动覆盖，内存仍可导出；未保存离页提示。
- 按姓名列出本地角色；不把characterId、事件ID、commandId作为玩家输入。无变化时保存按钮停用，避免把“已经保存”错判成严格前缀冲突。
- 修复runtime行动数上限不对称：读取允许至10000，达到10000后新写在追加前拒绝；共享常量，不产生10001后下次无法读取的输出。尚未实测10000条完整大档的性能。
