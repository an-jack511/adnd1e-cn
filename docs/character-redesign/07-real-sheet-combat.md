## 已接通的任务

1. 打开现有核心单职业准入／运营档案，立即查看HP、参考AC、已取得等级与XP。打开后收起本地角色选择区，避免库管理表单占据人物卡顶部。
2. 选择目标AC −10..10，查询DMG职业原表目标；默认不启用战士每级进步选项。保留重复20、超过20、零和负数，不用THAC0平滑。此动作只查表，不自动决定命中。
3. 同屏显示五类职业基础豁免。明确排除能力、种族、职业特别加值、魔法、情境修正；不能拿它冒充最终豁免。
4. 从库存实例选择团桌已完成的普通护甲、盾牌穿戴，或明确无甲／无盾；预览后经统一Action提交、记录、自动保存。未选择前AC未知，不自动挑库存最优装备。
5. 展开属性原始骰值、创建调整值及已记录当前体质；未接入的其他当前属性、特殊力量和临时修正明确标为未接入。

独立面板位于 `src/character/ui/campaign-combat-panel.ts`；规则表、计算、公开投影、动作及持久化仍分层，不把原始运营模块交给玩家页面。

## 原始事实与事件

`character.equipDefense` 变为 `record-defense`，只保存：

```json
{"armorItemId":"mail-one","shieldItemId":"shield-one","ordinaryEquipmentConfirmed":true,"note":"团桌确认实际穿戴"}
```

AC、无盾AC、DEX调整只由当前等级、库存、创建DEX和原表重新计算，不保存为唯一角色事实。不记录穿脱时间完成、不自动腾出双手、不花费旅行时间、不代替DM确认情境。

不存在的装备、魔法重量标识、未知／特殊定义、不合职业的装备会拒绝新确认。之后物品消耗、放入背包、移入仓库或其 `worn` 子位置时，旧选择不再产生有效AC；显示待重新确认，不悄悄当成无甲。容器内装备必须先记录团桌实际搬运／取出，不能由工具自动拿出来。

独立审查发现“随身背包仍当穿戴”和“仓库worn子位置绕过检查”两个同源问题，主任务采纳而非以方便保留：立即位置与完整祖先链均须是人物／穿戴位置；增加两个回归负例。历史穿戴动作仍在事件链中。

未发生新动作的历史档案不新增defense字段，保持重放兼容。含新动作的文件必须由认识该动作的读取器处理；旧程序应拒绝并保全，不丢弃尾部。当前仍沿用运营schemaVersion1，统一1.1迁移／能力协商与安全公开分享包尚未完成，这是发布门槛，不用新UI掩盖。
