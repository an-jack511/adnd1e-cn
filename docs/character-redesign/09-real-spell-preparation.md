# 正式人物卡：法术书、准备、消费与战役时间

2026-10-17。Phase B增量；全系统目标继续有效。不是完整高环神术目录、多职／双职或所有施法职业运营的发布认证。本轮没有推送远端或迁移线上存储。

## 功能与模块

- 人物卡“法术”区显示每环可用份数／已核容量、逐份施放入口、已消耗记录与书内／神术选择依据；分区导航可直接到达。
- `character.prepareSpells` 经现有预览、当前策略提交、事务、事件和IndexedDB自动保存处理。取消或失败不改变档案；不用玩家填写事件ID或来源ID。
- 奥术从现存书内条目选择本次学习份数；不重掷Chance to Know、不凭容量授予新法术、不自动取得书本。
- 神术从已核一级清单及档案已有公开定义选择，要求明确本次实际授予；每份创建新的公开授予事实，旧grant不是永久许可，不重建神明机密或来源实体。
- 原有可用准备保留；新准备生成新副本。旧施放记录、旧副本与实际授予均保留，不把“恢复”实现成清空历史后重置。
- 准备只处理实际完整休息及学习／祈祷，不恢复受伤HP、不自动扣食物或材料、不等待现实时间。

## 时间与原始事实

准备动作保存选择身份、数量、实际休息／学习起止、地点、明确确认条件及自动绑定的最后施法身份；不保存手工最终容量。容量、最高环休息要求和学习总分钟重新计算。

世界时间为从战役第1天起算的整数分钟。已有日历沿用原单位；没有日历时须明确采用长度，不默认24小时／7天。普通UI可明确建立24小时一天、7天一周；已有非24小时日历使用“第几天／当日第几分钟”，不强套现代日期。

正常首次流程为完整休息后立即学习；同一实际休息也可接续多段学习，不每份再收4小时。UI提供接续上次休息选项及其实际日期；之后一旦有施法，旧休息不可再用。工作流还可核对日历里原已存在且完全匹配的实际休息。

进入日历后的新消费必须记录战役时间，并检查副本已经准备完成、施法顺序与完整休息。旧无日期消费继续保全，不捏造其世界时刻；首次恢复前须明确确认这次完整休息在该历史消费之后。该确认是本地事实，不是远端DM签名或可独立证明的缺失时间。

课程保存对实际rest／study活动和此前casting集合的引用，派生副本保存来源与session。后来改动日历或补入施法事实时，重放仍核对课程证明；普通重叠备注不能维持一个已经矛盾的收益。

## 交叉审查与最终决策

延续Phase A三视角立场，但本轮没有虚称重新运行三位角色的完整独立研究：一位独立编码者完成四职业真实准入fixture，另一位独立规则／代码审查者检查本轮准备模块。历史、DM与PL之间的产品取舍由主任务负责：

| 争议 | 决定 | 原因／落实 |
| --- | --- | --- |
| PL希望一键恢复，历史／DM要求时间与实际世界条件 | 不采用“一键补满”；选择份数、软件计算要求、确认实际完成 | 保留规则，不把每个内部事件变成表单字段 |
| 是否每次点准备都重新收完整休息 | 不采用 | 同一rest支持连续study，按最高拟恢复环决定一次最低休息；保留各学习区间 |
| 神术是否可以复用上次grant | 不采用 | 本次授予另记事实，玩家勾选不是自动神明批准，也不是身份认证 |
| 最后追加cast等于世界时间最后施法？ | 独立审查提出P2反例，采纳并修复 | 检查全部已知施法时间；课程记录此前casting集合；重放拒绝前后次序矛盾。复核后关闭P2，报告保留反例与修复证据 |
| 只显示“成功”还是明确知道准备了什么 | 采用名称、份数、世界日期和前后可用总数预览 | 不展示记录ID；同时说明HP、食物及材料没有自动改变 |
| DM复杂兼容裁定是否由普通checkbox承担 | 不采用 | 普通流程遇占时冲突、中断、换地点或历史矛盾会停止；不能把拒绝当成RAW禁止一切工作 |

最后一项仍有产品缺口：专用中断／兼容裁定、撤回既有收益与依赖纠错尚未接通。当前不能仅靠一条“理由”覆盖冲突；也不能以此声称DM例外工作区已经完整。
