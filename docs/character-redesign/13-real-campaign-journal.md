# 正式战役记录与实际活动

日期：2026-10-17。增量实施，完整系统目标仍未验收。

## 页面与边界

`/character/journal/` 现为真实角色档案工作区，不再将普通战役导航指向巨型团务表单。人物卡、成长和战役记录携带同一角色/分支，使用原有 IndexedDB 角色库、自动保存、规范重放及下载文件；高级工具保留于折叠区。创建仍使用现有向导，尚不是四页面最终全部完成。

时间线按档案追加顺序倒序显示，公开详情逐条展开。每条独立显示录入时间和战役时间：未记录的战役日期不根据电脑时间、后来的日历配置或别的动作补造。公开只指字段范围，不代表联网发布。

新增安全切换人物：仅当前快照已保存且无保存/读取操作时退出当前工作区；原角色留在本机，重新选择既有角色。不删除角色、不自动合并、不丢弃未保存进度。

## 架构与隐私

- `application/campaign-journal.ts` 先正式读取/重放，再从每个动作对应的已验证历史模块快照建立白名单投影。
- 投影字段限姓名、已取得等级、内部修订、当前日历单位及条目序号/中文标题/分类/录入时刻/当时战役时间/公开说明。内部修订不在默认页头显示，不与schema版本混淆。
- 训练时段按精确训练活动身份与角色匹配，不拿同起始时刻的另一人物活动替代。补录过去日期保留原条目与后来的补录条目，不重写过去看起来“早已知道”。
- 不传完整事件、模块JSON、来源ID、actorId、钱包ID、位置ID、DM理由、自由裁定文字或法术私有说明到renderer。未知但读取器支持的未映射动作保守显示通用记录；未知格式动作仍由规范读取器拒绝。
- `ui/campaign-journal-panel.ts` 只消费公开投影并转义文本；不写档案。查看/展开/刷新不增加revision。

完整角色导出仍是用于本地保全的正式运营文件，可能含审核信息；不能把页面公开投影安全性等同于完整文件可以公开分享。独立的可分享完整人物档案仍需后续验证。

## 实际活动 Action

`character.recordActivity` 通过独立 `actions/journal-actions.ts` 与 `ui/journal-activity-panel.ts` 接收实际类型、起止战役分钟、地点和已发生确认。普通界面不收事件ID、角色ID、来源ID或重叠裁定结构。

允许记录原有分类中的旅行、冒险、休整、学习、语言学习、法术研究、魔法物品制造及其他活动。故意不提供普通“训练”类型：训练必须经过成长向导，不能用通用时段伪造进度。

要求已有明确日历、正向非零时段，交给现有 `schedule-activity` 原子执行。重叠不能在此自动批准，不能注入兼容性或规则例外；冲突显示可理解的提示并保持原件不变。实际地点/行程作为正式事实保存，不将内部位置标识直接泄露到公开时间线。

本动作只登记实际占用。它不证明研究成功、不制造装备、不学会语言、不授XP、不付工资、不恢复HP或法术，也不自动核定成本。完整研究/制造/休整结算与资源交易需要专用有原书依据的流程，仍未完成；这不是以时间登记替代那些功能的最终设计。

原有经验与实际钱币收入快捷操作也可从本页开启，沿用现有成长 Actions 检查、预览、原子提交和自动保存。
