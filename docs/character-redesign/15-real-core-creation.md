# 核心创建真实浏览器验收记录

验收日期：2026-10-17。范围先收敛为 PHB/DMG 核心单职业创建与正式人物卡入场；UA、OA、WSG 等拓展不作为本记录的完成条件。

## 实际路径

在本地静态站点中用真实浏览器从属性阶段开始，创建了测试角色「晨星·创建验收」：

- 属性方法：DMG III；浏览器实际生成并保留六项原始骰池，最终属性为 STR 12、INT 18、WIS 14、DEX 16、CON 12、CHA 15。
- 身份：人类、男性、NG、单职业魔法师。
- 一级生命值：实际记录 1d4 骰面 3，当前 HP 未在入场时虚构为满值，正式档案显示“待确认 / 最大 3”。
- 起始金钱：实际记录 2d4 骰面 1、4，共 50 gp。
- 语言：自动语言、阵营语言和 INT 18 的 7 个额外语言位分别记录；每个普通语言选择都保留 DM 确认。
- 武器熟练：记录匕首；职业允许检查单独保留。
- 装备：记录一把 Dagger and scabbard，实际单价 400 cp，按原书币值交付 2 gp；采购结算后账面为 48 gp。装备是否实际穿戴没有被自动推断为 AC。
- 初始法术授予：记录 DMG p.39 的攻击、 防御、杂项骰面 6、7、2，得到阅读魔法、魔法飞弹、护盾术、侦测魔法。
- Chance to Know：实际输入四项计划法术的实体 d100=1，并继续录入直到 INT 18 的 18 项检查停止；原始骰史保留，未用“最低 9 项”自动补发法术书。
- 法术书取得：逐项填写导师／书页来源、访问确认和成功取得结果。正式档案显示 4 项书中法术、0 项已准备副本；“理解”“持有书页”“准备”保持分离。
- 灵能：战役明确选择不启用 PHB 灵能，系统记录 disabled；没有生成能力数量或模式。
- 战役约定：记录战役名、DM 身份、起始地点与测试说明，交给审核页。

## DM 审核与正式入场

审核页从本地创建库读取同一个 creation ID，分别确认装备、初始法术和战役入场三个 `needs-dm` 任务，再记录正式准入。正式人物卡通过已有角色库写入，使用 `character=e3bb4982-d131-4f9f-a9fc-b8e9b305fd8c&branch=main`，没有建立第二套角色数据库。

浏览器第一次刚跳转到审核页时仍显示“等待导入”；刷新后按 query 中的 creation ID 正确恢复修订 12 的创建记录。这说明当前恢复是异步的，后续应把“正在读取本地创建库”作为明确加载状态继续改善；本次不把第一次中间状态冒充成功。

## 规则与数据边界

本记录验证的是现有已核来源与明确战役采用的流程，不声称 PHB p.10 与 DMG p.39 的所有解释已经消除歧义。初始法术 adapter 明确记录来源、Chance to Know 骰史、实际取得证据和“未准备法术”事实；没有自动赠送法术、扣除转录费用、填入训练时间或改变 DM 裁定。

原书来源链在审核页可展开：PHB 原书 p.10、p.12、p.15–17、p.19、p.25–26、p.34–37；DMG 原书 p.24、p.37、p.39。PDF 页码只作为项目文件定位，不替代原书页码。
