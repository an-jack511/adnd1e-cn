# 核心法术生命周期实测

日期：2026-10-17

## 验收对象

- 本地开发预览：`http://127.0.0.1:4321/`
- 角色：`牧师核心验收`
- 档案：人类、牧师 1 级；1 环神术容量 3；初始创建阶段记录为“本次未授予／暂不准备”
- 规则边界：只登记团桌已经发生的授予、休息、祈祷、准备与施放；不由程序凭空授予法术，不用准备动作恢复 HP，也不自动处理组件与效果裁定

## 实际流程

### 1. 记录神术准备

在正式人物卡点击“祈祷与准备”，选择 1 份“祝福术”，并填写：

- 战役第 1 天 08:00 开始完整休息
- 实际完整休息 8 小时
- 实际连续学习／祈祷 15 分钟
- 地点：神殿
- 确认完整休息、时间地点真实、施法后无未记录干扰，并由 DM 确认本次授予

系统预览结果显示：第 1 天 08:00 → 16:15；祝福术 × 1；可用准备 0 → 1；不恢复 HP、不自动消耗食物。确认应用后，人物卡显示“祝福术 · 一份可用准备”。

### 2. 记录施放

点击祝福术“施放”，填写：

- 团桌已确认组件与情境
- 实际效果说明：神殿中的祝福术测试
- 实际施法时间：第 1 天 16:30

预览显示消耗祝福术一份；不自动治疗、造成伤害或扣除材料。确认应用后，人物卡显示 0 / 3 可用准备，并出现“已消耗记录（1 份）”。

### 3. 刷新与持久化

浏览器刷新后仍显示：

- 1 环可用准备：0 / 3
- 已消耗记录（1 份）
- 最近活动包含“完成法术学习／祈祷”和“消耗准备副本”
- 本机档案已加载并校验

这验证了法术准备与施放不是临时 UI 状态，而是写入同一角色档案并能在刷新后恢复。

## 规则与产品边界

- “本次请求并实际获授的法术”与“本次未授予／暂不准备”是两个明确分支；不因角色有法术容量就自动产生神术。
- 准备数量受当前法术容量与所选份数检查；旧的未消耗准备不会被静默覆盖。
- 休息、学习／祈祷、地点、日历和干扰确认均作为操作事实记录；中断或非普通流程需要 DM 处理。
- 施放只消耗准备副本并记录时间与玩家提供的效果说明；实际目标、范围、豁免、伤害、持续时间和材料由团桌与 DM 裁定，当前页面不冒充 VTT 或自动裁判。
