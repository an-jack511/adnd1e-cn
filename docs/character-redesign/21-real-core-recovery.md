# 核心档案历史恢复实测

日期：2026-10-17

在已有正式运营档案上刷新人物卡，确认高级区提供“历史快照与恢复副本”：

- 当前档案第 16 代，历史区显示第 15 至第 11 代五个受限快照。
- 每个快照只显示代数、修订号和动作数量，不向普通界面泄露完整事件载荷。
- 点击第 15 代“导出恢复副本”后，页面提示“当前角色未回滚，较新事件未删除”。
- 底层使用精确存储 token 和快照代数重新核对基线；若另一页面先保存，恢复请求失败且当前档案不变。
- 恢复动作只导出可独立保存的运营档案 JSON，不覆盖当前槽位，也不删除历史。

这保留了本地静态应用无身份认证条件下的审计边界：恢复是可审阅的冲突副本，是否把它作为新分支或 DM 认可的档案由团桌决定。
