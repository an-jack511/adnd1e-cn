# 公开关系投影与 DM Studio 边界

状态：已接入玩家运营档案；DM Studio 仍是未来独立项目。

## 当前站点做什么

玩家档案可以接收版本化的 `adnd1e-relationship-player-projection` 文件。导入动作会：

1. 绑定当前角色 ID；
2. 严格检查格式、版本、关系类型、合同字段、支付字段及唯一 ID；
3. 只写入玩家公开关系模块；
4. 要求外部投影版本号不倒退；
5. 通过正式 campaign action 写入，因此可回放、导出、保存和恢复。

人物卡只显示姓名、随从/雇员类型、公开状态、合同起止、薪酬、职责、供给、装备、公开支付和公开历史。

## 明确不做什么

当前站点不创建招聘审批、不要求玩家填写 DM 身份、不执行忠诚或士气检定，也不展示真实阵营、宗教、性格秘密、接受骰、忠诚分数、士气骰和主持人备注。这样不会把 DMG p.36–37 的私密裁定错误地变成玩家端的可编辑数字。

未来 DM Studio 产生公开投影时，必须使用这里定义的公开白名单；玩家站点只接收投影，不把投影反向解释成私档，也不把本地导入当作身份认证。

## 原书边界

当前可计算的关系事实仍限于已核验的 PHB p.13、DMG pp.34–37 与 DMG p.67：魅力决定随从人数上限；随从与普通雇员/佣兵分开；招聘报价、忠诚与战斗士气是不同层次。未完成的雇员费用/可得性全表和职业高等级随从表继续标为未核，不由界面补齐。
