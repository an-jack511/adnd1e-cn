## 可以实际操作什么

四视图共享一个内存里的虚构人类魔法师。创建可执行已核 DMG I–IV 算法，选择示例骰点贯穿六步；资格、HP、初始金钱和固定初始授予调用现有计算。生成前显示未完成事项与替换确认，不声称正式准入。

人物卡可预览并应用正 HP 伤害、实际治疗、逐份法术消费、火把使用；展示新核验的魔法师低级攻击列与五类基础豁免。成长演示经验结算、E 评价导师路线的时费、实际课程登记和模拟成长；研究只登记意向，没有成功或收益。

演示导出格式为 `adnd1e-design-prototype` / `0.1.0` / `synthetic:true`，文件名 `design-demo.prototype.json`。仅回读这种演示文件，拒绝真实档案。不写 IndexedDB、不覆盖角色；刷新会重置，不是自动保存。文件里不含完整生产创建骰史、DM私档或完整审计证明。

## 第三轮：冲突与决定

| 争议 | 批评与决定 | 具体落实 |
| --- | --- | --- |
| 容易使用是否等于隐藏规则成本 | A 反对只看数值的一键升级；C 要求不翻多页后台 | 采纳两者的非冲突部分：成长任务解释费用、时间和未授级状态；来源按需展开。拒绝跳过训练，不采用数值等级编辑 |
| 原型是否必须接真实档案 | B 希望检验既有守卫；A/C 指出这会把 Phase A 扩张成整套生产集成 | 本期采用可执行的隔离内存情境，不宣称真实守卫端到端已集成；生产 Action 仍必须适配现有 parser/commit。不是两套正式数据库的“折中” |
| 合成训练计算能否称作正式授级 | A/B 明确反对；C 允许有边界的演示 | 接受反对：按钮和结果标为模拟成长，注明导师、实际时间和无冲突前提；正式授级验收单列，不能凭原型通过 |
| 撤销等于倒转世界？ | B 要求保留依赖、事实纠正与补偿区别；C 要快捷纠错 | 原型仅撤回最近演示结果并追加撤回说明，不能连续撤销早期事件；正式“纠错”必须依赖分析，不提供删除历史的捷径 |
| schema1.1是否已经统一 | B 指出适配器缺失，C 指出用户无法分辨档案 | 采纳：沿用已有候选，不再造第三个生产格式；提供逐种映射和保全计划，明确当前并未迁移成功 |
| 私密信息展开折叠是否足够 | A/B 反对只在UI隐藏忠诚/研究秘密 | 采纳：生产只传公开投影，私档不得进入玩家DOM、导出或缓存。原型不含私密事实，不能以此证明生产安全 |
| 移动端如何保留规则深度 | C 要常用操作直达；A 不允许删规则 | 采用底部导航、分区与来源弹窗；不减少规则。复杂恢复、扩展等未接通要明确停下，不伪装一键长休 |
| 功能是否应一次性全部上新 | 用户要求研究先行、保留已可靠逻辑 | 四视图原型与现有路由并存但明确隔离，不加入正式导航；生产切换必须逐阶段通过迁移及回归门槛，之后撤掉重复旧入口 |

## 规则研究的诚实范围

本轮主任务重新读了 DMG 属性页文本，查看了 DMG 印刷74/75/79及 PHB11/36原页图；实际接入数据只取 DMG74魔法师1–5攻击列、79同等级豁免行及 PHB11/36 的通常无甲防御依据。其余索引沿用已署名核验的共享证据与规则包，不冒称本轮重读了所有原书。原页图临时渲染移至系统临时目录，不作为网站公开素材。

PHB、DMG、MM、UA、OA、FF、MMII、DSG、WSG 原件均在本地找到。FF/MMII没有完成本轮逐条人物规则审计；“文件存在”“规则包存在”“数据已核”“人物全过程可玩”是四种不同状态。没有一个可信分母，不能报一个好看的总体规则覆盖百分比。

## 总验收回答

“从未读完规则书的玩家，能否正确创建、升级、长期运营角色并逐处找到依据？”——**目前还不能把答案判为是。** 原型证明了信息架构和有限操作路径；语言/年龄等创建事实、全职业矩阵、真实重新准备、全生命周期适配、统一导入迁移与自动保存仍是明确门槛。下一阶段先完成统一正式人物卡与档案接续，而不是增加旧运营页表单。
