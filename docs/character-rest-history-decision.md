# 多次零 HP 事件的休养历史与后果检查 v2

日期：2026-10-16。实现长期历史保全，不新增 AD&D 规则、改变最低休养长度或引入后世版本。沿用已核 DMG82/86 的资料与前轮后果检查依据。

## 问题

当前 `lifeRecovery` 合理地表示最近一次恢复，但下一次零 HP 事件会替换它。若用这个字段充当全部已完成休养证明，更早期间会退出后补事实复查。这与持续战役世界的历史保全要求不符。

## 决策：从事件读取，而非改写旧档

新增 `completedCoreRestHistory`：仅从真实 `complete-zero-hp-rest` 行动对应的唯一 `character.module-replaced` 不可变事件快照提取完成声明，包括行动/角色裁定者标签、零 HP 事件、休养活动、原区间、完成确认时点及当时检查策略。它不读取当前 `lifeRecovery` 来代替旧期间，也不把派生索引写回角色文件。

它要求调用者传入已通过完整重放验证的档案；不是独立的通用导入验证器。选择器检查快照唯一性及所提取完成事实的一致性，输出与输入隔离。行动到事件以 command ID 建立一次索引，不对每条证明反复扫描全历史。

Heal 解除禁令不属于“休满完整期间”，不生成这种证明。此处的证明是可追溯的历史声明，不是多人签名、身份认证、真实团桌行为的密码学证明或无条件 RAW 认证。

## 检查策略版本

- 无标记及 v1：保留原重放语义，不因修复而偷偷改旧输出。
- v2：新授级/完整休养完成前，复查所有已完成完整休养期间，以及已有带日期课程，而非仅当前或最近一次恢复。后补较早期间的冲突必须重新裁定。
- 当前新写入只接受 v2；v1 与无标记完成只用于兼容历史。它是软件检查策略，不是 AD&D 2e，也不是新的房规开关。

重放过程维护过去完整休养活动的只读索引，用于后续 v2 检查；不会新增旧快照字段。UI 从事件证明呈现全部期间及策略，并把旧期间的未决后果加入既有裁定面板。旧检查不自动升级为新认证，已授等级不自动删除，HP 不自动改变。

## 验证

完整创建生命周期分支连续完成三次独立零 HP 恢复，确认首次完成声明在后续事件后逐字段保持不变。补记首次休养期间的研究后，第三次完成的 v2 写入被拒绝；记录明确历史例外后才可完成，全部 JSON 重放一致。

另构造明确标注为合成的混合策略兼容历史，确认 v1 的旧行为仍可重放，而相同 v1 操作不能在当前写入口提交。该夹具不是旧软件真实生成文件的证言，也不覆盖所有历史版本迁移。

专项验证按 command ID 关联而非当前快照、缺失/重复事件拒绝、不一致模块/事件/区间/完成值拒绝、Heal 排除、legacy 标识及输出修改不回写。所有证明仍依赖原档通过重放验证；不声称已经完成固定规则引擎全部版本支持。

剩余范围：旧授级缺少带日期课程记录时的完整人工修复，旧历史自动撤销/更正，全历史世界位置/时间连续性、多/双职业及扩展，以及这些新界面的浏览器生命周期验收。
