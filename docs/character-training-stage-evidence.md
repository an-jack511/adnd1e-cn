日期：2026-10-16。主 Agent 复核原件并处理历史设计立场审查 H01，不冒称独立子 Agent 又完成了一轮研究。规则范围是 PHB/DMG 普通核心职业，不覆盖 UA/OA 或 Bard 专门学费程序。

## 采纳与不采纳

采纳 H01：阶段必须由当前已经取得的职业等级与称号表确定，不能用拟取得等级提前切换，也不能用通用费用理由或门槛确认绕过。低于该阶段时拒绝名号方案；达到后拒绝继续套用低级导师方案或双倍时费的低级自修例外。低阶段自修的表现评分限制继续由原引擎处理。

不采纳“所有职业一律九级”或“达到名号就是不必花时间”的简化。DMG86 的名号后程序仍按表现对应的周数自行训练/学习，四个基础费用族分别计算，游戏时间仍需记录。

费用解释边界：DMG86 的金额表只列 cleric/fighter/magic-user/thief 四个标签。本轮不把子职业或武僧强塞进某个“已核原书专属费率”。四个同名基础职业不得任挑别族以改变费用；其他职业仍需 DM 明确记录采用解释，并在界面提示其不是本轮认证的逐职业印刷金额映射。完整房规覆盖流程尚未接入时，不能用普通理由伪装改写阶段；专门变体需另行标记和实施。

## 实现和验证边界

`rules/core-training.ts` 保存称号/等级/PHB 来源对照；`engine/core-training-stage.ts` 仅计算阶段和四个直接列名的费用族，不授级、不消费费用。两个工作流计划入口执行守卫；UI 根据当前等级禁用不适用路线，并显示称号、阶段和来源。

`test-core-training-stage.ts` 对十职业的阈值前、当级和阈值后逐项测试；对升到名号本身的课程保留低阶段程序；测试同名基础职业费用族限制、名号后 S 评分为两周而非四周、普通理由不能绕过阶段。Druid/Monk 等高阶名额/决斗门槛在测试中通过独立 DM 门槛处理，不因选了名号方案自动满足。子职业及武僧费率样例仅作采用解释测试，不是 RAW 金额认证。Bard/扩展职业拒绝进入此判定函数。

生命周期集成测试另验证一级战士开启候选后不能提前采用名号方案，失败不修改档案。既有合法路线输出事实结构不变；新增守卫可能拒绝旧代码曾错误接受的跨阶段档案，不能静默改其费用或删除历史。此类原文件仍需通过原件保全/隔离检查处理，本轮没有设计自动历史修正迁移，也不宣称固定规则版本重放的长期需求已经完成。

H01 的普通核心阶段漏洞得到处理，不代表 H03 经验溢出、H04 无日历训练、H05 冲突后果及 H06 时点/地点连续性已经解决。
