## 当前目标与工作顺序：先建全术语库，再查全站一致性

本任务先完成术语库，再开展逐词的全站一致性核对。不得被少数已经指出的问题牵着走，也不得在词库尚未覆盖原书前反复检查同一批熟悉词条。

1. **原文扫描与术语建库。** 术语库只收录从 AD&D 1E 资料库原书与主要拓展英文正文、标题、表格、脚注、附录和索引中确认的词项；尽可能提取规则术语、法术、物品装备、职业种族、人物地理、怪物、生物、组织、设定、动词及其他专名。OCR、底稿和现有页面只作候选入口，逐项回到 1E 原文上下文，去重并记录页码、词形、类别和适用语境。3R、5E、5R 的词项只用于检索 1E 词项译名，不作为本词库独立收录来源。
2. **每个术语只走两步：找到术语 → 找到译法。** 先确认原文词项和语境，再按 **3R → 5E → 5R** 查找可用、准确对应的中文译法。找到语义相符的既有译名时，按版本优先顺序采用，并保留版本差异；名称相同不代表机制相同。
3. **找不到现成译法时完成自译。** 依次查过可用来源后仍未找到适用译法，或来源无法访问时，继续按既有术语规律、D&D 中文翻译惯例、词素含义和原书上下文自译，给出可用的中文主译。记录已查来源、未能读取的来源、自译词素／构词理由及适用范围；以 `adapted-variant` 标记已完成的规范化自译，并在 `verificationScope`／理由中注明 `self-translated-after-3R-5E-5R-search`。不得仅因外部索引无结果或页面 403 把条目留空或挂起，也不得把自译说成官方译名。
4. **词库覆盖完成后再逐词核对全站。** 完成计划书目与页段的原文覆盖，确认每个候选已有中文主译、英文异体与类别，或有明确的原词辨识问题记录后，才对词库逐词扫描所有网站页面、标题、表格、目录和跨书引用，统一同一语境下的译名并修正漏译、半译和错误混用。建库阶段不做全站逐词一致性巡检。
5. **最后进行逐页与跨页综合审查。** 按原书完成翻译完整性、规则准确性、中文流畅度、排版一致性、深色模式、续页标记、图片冗余与裁剪、AI 说明痕迹等检查；这些项目不得取代或打断前两阶段的术语库主线。

“完成词库”以 AD&D 1E 原书和主要拓展的覆盖清单、候选处理结果为准，不设总量上限，尽可能收录全部经原文确认的有效术语。20,000 项是规模预期而非封顶或完成条件；若去重、排除噪声后原文有效术语确实不足该数，才以完整书目／页段扫描记录说明，不为凑数收录噪声。3R／5E／5R 仅作为译名检索证据，必须附着于对应的 1E 原词条；不得将后续版独有词项批量并入术语表、网站查词页或开放 API。优先逐一处理原文候选并保留原书定位；OCR、底稿译文及既有网站中文一律不能单独作为正确译名证据。

### 每个术语的译名查找顺序

- 先确定英文原词、书名、页码、词性与规则／设定语境；同一词在不同语境中可拆成不同条目。
- 再按 3R→5E→5R 查相同英文名称的可靠中英对照。只有词项精确对应且中文语义适合 1E 上下文时才采用；近似词、不同子系统或机制不同的词只作线索。
- 同一英文词在不同规则、设定或词性下有多个义项时，按原文逐处判义并分别标注适用语境、中文义项和来源页码；无法共用一个主译时拆分语境记录或列出义项，不能仅按拼写统一。将词义差异写入词库/API 可读取的语境说明，便于人工与 AI 按上下文选译。
- 若未找到可用译法，按已有术语表的词素和规则构词、D&D 中文惯例及现代中文表达自译。自译必须有 1E 原文出处和简短构词说明，旧译可列为搜索别名，不得替代新主译。
- 搜索受限要记录具体范围，不推断某版本“没有译名”；搜索无结果也不是延迟自译的理由。
- 日常译名核查优先使用已下载的离线参考数据库，按 3R→5E→5R 查询；不逐词重复访问 wiki。`npm run terminology:cache` 用于显式下载／续传，`npm run terminology:lookup -- "英文词项"` 全程离线；审查批次自动合并本地索引。只在缺项、义项不清或需刷新时联网。3R 当前仅有部分证据，不能把本地无匹配说成该版本无译名。原始 JSON 不进入 1E 正文／发布物，标题命中仍需结合原书语境判断。
- `pending` 只用于英文原词、OCR 内容、指称对象或关键语境尚不能确认的情况，不用于“后续版本没有检到译名”。能确认术语的，必须选定中文主译并继续推进。

## 翻译与术语要求

### 已确定的固定译名

- `Magic-User` 统一译为“魔法师”；`magic-using creature(s)` 在表示具有施法能力的生物时统一译为“施法生物”，不使用生硬的“魔法使用者生物”。
- `proficiency` 泛指通过训练或实践获得的熟练程度时译为“熟练”；指可计数、可取得的规则单位时译为“熟练项”。具体术语包括“武器熟练项”“非武器熟练项”“角色熟练项”“荒野熟练项”“地城熟练项”“工匠熟练项”“蛮族熟练项”“通用熟练项”“宫廷熟练项”“骑乘熟练项”“划船熟练项”“空中骑乘熟练项”“植物学熟练项”“文化熟练项”“驯兽熟练项”“陆地骑乘熟练项”“龙骑乘熟练项”“绳索使用熟练项”“熟练项检定”“熟练项栏位”等。
- `proficiency` 只有在明确表示专业领域、专长领域或一般特长时才译为“专长”；不能把规则熟练项机械改成“专长”。“专长”可作为旧译别名保留在中英术语表中，但不作为正文主译名。
- 核心规则名词按语境固定区分：战斗时间 `turn` = “回合”、`round` = “轮”、`segment` = “段”；`spell level` = “法术环级”、`spell slot` = “法术环位”、`caster level` = “施法者等级”。法术书容量、费用、经验值或学习时间按法术级别计算时用“环级／每环”，不得误写为施法者的“环位”。
- 六项属性统一为 `Strength / STR`“力量”、`Intelligence / INT`“智力”、`Wisdom / WIS`“感知”、`Dexterity / DEX`“敏捷”、`Constitution / CON`“体质”、`Charisma / CHA`“魅力”；`Wisdom score` 译为“感知值”。只有明确指属性时才将 `Wisdom` 译为“感知”，普通语义仍依上下文译为“智慧”等，不得盲目全局替换。
- `THAC0` 等规则缩写、属性代码和骰式按规则惯例保留；具有实际语义的法术、物品、装备、职业、种族、人物、地理、怪物、规则动词和设定名词仍须使用中文主译名。
- AD&D 1E 的 `Breath Weapon` 统一译为“喷吐武器”，豁免类别译为“对喷吐武器豁免”；“吐息武器”作为新版语境的译法记录为版本别名，不混入 1E 正文。
- 标题中的中英对照不加括号；中文为主标题，英文为辅助标题。正文替换英文后，清除仅为中英混排留下的中文间空格。

- 逐页检查：大标题、中文段落、表格标题、表头、表格单元格、脚注、图注和交叉引用中的英文均须有中文对应。
- 审查时先区分英文的功能，不把所有英文都当作漏译：THAC0、AC、HP、HD、STR、DEX 等规则缩写/属性代码，骰式、单位代码、来源代码、书目代码和格式必需的英文可保留；这类保留不计为翻译缺失。
- 必须翻译具有语义的名称和规则词：法术名、魔法物品名、武器与装备名、职业与子职业、种族、角色/人物、地理、怪物、其余规则名词与动词，以及战役设定名词等。英文原文可在首次出现、表格双语列、英语副标题或专名需要时作为辅助保留。
- 中文标题和中文正文中的语义专名必须使用中文译名作为主要显示形式：人物、神祇、组织、种族、地理、城市、国家、怪物、法术、物品、装备及其他设定名称不得只保留英文，也不得出现“Southern 艾尔戈斯”这类中英混排。英文可在英语副标题、原书标题、双语对照表、来源核对位置或首次出现的括注中作为辅助信息，但不能替代中文正文中的译名。
- 对已确认译名的专名，跨页、跨书统一使用同一中文形式；存在不同版本译名时，在站内“中英术语对照表”或审查记录中保留英文、中文及核对状态，供后续复核。
- 中文译名替换英文后，须删除原先为英文与中文混排而保留的多余空格；中文与中文之间不得留空格。只有英文原名、缩写、代码、数字单位或确需分隔的中英对照仍保留空格。
- 首次出现的必要英文术语可采用“中文（English）”；同一书内及跨书相同规则概念必须统一中文名，除非来源明确要求区分。
- 规则缩写可保留，但正文首次使用时应有中文释义，或上下文已明确其含义；不能用缩写掩盖应翻译的完整规则名称。
- 英语副标题、版权页、出版信息、专名原文、咒语/誓言等格式或内容上必须保留的英文不强行翻译；这类保留不等于漏译。
- 同一英文词不得在相同规则语境中随意切换译法；若确实存在版本、职业、世界观或规则层级差异，须在术语表或审查记录中说明。
- 发现翻译不完整时，优先补齐原意，再做中文润色；不得用概括代替规则细节。

## 排版、分页与图片要求

- 同一书、同一类页面的标题层级、中文/英文副标题格式、表格对齐、来源行、页码行、列表和图注保持一致。
- 书籍阅读模式按内容连续阅读；不要把原书因分页产生的“（续）”“（再续）”“（续完）”“Continued”等标记继续作为 wiki 分节标题。可保留真实文章名称中的“继续”“未完待续”等含义，但不能把单纯分页标记当作新的章节。
- 跨页内容应合并到同一语境下，保留必要的原书页码来源标记；页码标记不能破坏标题层级或制造重复章节。
- 深色模式下检查正文、英文副标题、来源行、表头、链接、选中状态、边框和输入控件的对比度；禁止使用仅在浅色背景可读的硬编码深色文字。
- 删除重复图片、裁剪不周图片、模糊或无必要的原书文字扫描图；保留裁剪良好、清晰度尚可且确实有规则/叙事价值的插图、地图、图表或版式示例。
- 发现无法安全自动修正的图片问题，记录文件、页面、问题类型和建议，不用猜测替换素材。

## AI 痕迹与编辑说明

- 除首页允许保留的翻译声明和版权声明外，公开页面正文、章节标题、表格、图注、来源说明和页脚不得出现“AI”“GPT”“人工智能生成/翻译”“按原书概括”“不能简单套用”等工作过程说明。
- 如果内容与原书不同：优先按原书补全并忠实翻译；确需概括、节选或删改时，只使用简明、事实性的编辑说明，例如“按原书概括”“未采用 XX 规则”“节选自原书”“较原书有删改”，并放在明确的编辑说明位置。
- 不把尚未核对、来源不完整或仅为建议的内容写成“原书规则”；不把本项目的实现限制写成玩家规则。
- 修订机械、过短、缺主语、中文逻辑不自然或明显由英文逐词映射而来的句子；以忠实、清楚、可检索为优先。

## 工作方法

1. 开始时检查工作树、原书文本覆盖清单、当前词库及未提交改动；保留与本任务无关的工作。
2. 按书目／页段扫描原书英文，依规则、法术、怪物装备、专名等类别提取词条；遇到新词先查 1E 上下文并去重，不先做全库同译巡检。
3. 对每个确认词条按 3R→5E→5R 搜索可采用的现成译法；未找到时依据既有术语、中文 D&D 惯例与词素自译，填入主译、词形异体和适用语境。以 `verificationScope` 与理由记录找到的来源或自译依据；外部来源不可访问不作为停工条件。
4. 更新主术语表后，重生成网站目录、检索数据、开放 API 和父目录导出；新词条没有中文主译不能视为入库完成。
5. 当主要原书与拓展的覆盖清单完成、每个候选均有明确去向后，再按词条扫描网站全部正文、标题、表格、目录和跨页引用，统一译名并逐项修订。
6. 全库一致性阶段完成后，再按整本或半本书做翻译完整性、中文润色、版式、深色模式、续页标题、图片和 AI 痕迹审查；至少运行与该批改动直接相关的数据核对，排版问题需检查浅色和深色呈现。
7. 每批在审查台账记录书名、页码／章节、词条类别、译法来源或自译理由、工作阶段、修订计数和待续入口。

## 修订计数与留档节点

- “修订 1 处”按一个独立可复核的内容改动计数：一个术语统一、一个漏译补全、一个句子修订、一个标题/分页标记清理、一个排版规则修正或一个图片处理决定均可计 1 处；纯生成文件同步不重复计数。
- 使用 `docs/long-term-wiki-review-ledger.md` 登记累计数、批次、文件范围、验证结果和提交哈希。
- 生产构建约每累计 500 处内容修订集中执行一次；以台账中的“最近一次成功构建累计数”为基准。两次构建之间先专注实质修改和必要的数据校验，不因小批修订反复构建；若改动风险或发布验证需要，可提前构建并记录原因。
- 每累计 200 处实际内容修订：完成必要的数据核对后，执行一次 `git commit`，随后执行一次 `git push` 作版本留档；无需对推送另行复核。生成文件同步不重复计数，未达到节点时继续推进，不为凑数空等。
- 以 `docs/long-term-wiki-review-ledger.md` 记录修订累计数及提交／推送节点；旧工时台账仅作历史记录，不再作为推送触发条件。
- 提交只包含本任务已明确审查的文件；用户原有的无关改动不得一并提交。

## 工作批次与汇报节奏

- 工作批次按完整一本书或半本书划分；完成一个批次后再做阶段总结，避免按零散页面频繁汇报。
- 对微校格式、表格密集或版式复杂的书，优先按半本书集中处理；若一本书内容较短，则按整本书完成后总结。
- 批次总结应概括该书或半书的翻译、术语、排版、续页标记、深色模式、图片和 AI 痕迹审查结果，并同时报告本周期修订累计数。

## 当前优先级

1. 逐页扫描原书英文、提取并补全尽可能完整的中英术语库；按 3R→5E→5R 先找现成译法，确无适用译法时再按现有术语与 D&D 中文惯例自译。
2. 原书覆盖清单完成后，逐词遍扫全站正文与跨页引用，统一规范主译、修正漏译和混译。
3. 完成上述两阶段后，再集中检查语句忠实与流畅度、排版、深色模式、续页标记、图片冗余／裁剪和 AI 说明痕迹。
4. 空格、括号和辅助英文显示等混排格式放在实质术语与内容修订之后处理。
5. 每个批次在审查台账登记覆盖范围、修改内容、构建和推送节点与下一批入口。

### 后置专项：DLA 中英混排

DLA 中英混杂严重：既有应译英文散落在中文标题、正文和表格中，也有中文译文夹在英文句子或名称内部，导致阅读混乱。此项明确后置：在主要规则书与主要规则拓展中的规则名词完成梳理、校准纳入术语库，并完成跨书译名一致性核校之前，不开始 DLA 混排专项，也不因 DLA 问题转移当前规则校订重心。上述规则阶段完成后，再集中清理 DLA 的漏译、半译、中英交错和标题/正文不一致。清理时逐项结合原文语境判断，不做盲目的全局替换；英文副标题、必要的原文对照、来源代码和格式必需缩写仍按前述保留规则处理。
