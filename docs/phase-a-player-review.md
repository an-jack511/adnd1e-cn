日期：2026-10-16。范围：现有路由、导航、界面源码与可复用工作流；提出 create / sheet / growth / journal 四个响应式交互原型的设计合同。本轮仅新增本文，不实现原型，不修改代码或既有文档。完成本文不等于 Phase A 原型验收通过。等待交叉批评后再收敛设计。

## 1. 证据口径与结论

主要问题是玩家必须理解“文件类型及模块边界”才能完成任务：旧人物表、一级准入展示、运营档案之间没有统一的当前角色工作区；日常行动与复杂成长程序混在一页。优先设计以角色为上下文的四视图，把已有命令包装成任务，不重新建立一套角色事实或数据库。

本文使用三种证据等级：

- **S（源码核对）**：直接阅读当前工作区文件，定位至路径及行号。工作区已有未提交改动；这是当前源码快照的发现，不保证其他提交一致。行号为本轮读取时定位。
- **E（共享核验）**：沿用 `X:/Games/DND/1e/docs/character-system-research/shared-evidence.md` 的署名核验结论；本轮没有重新打开英文 PDF 或视觉核对页图，不把他人核验写成本人核验。
- **D（设计建议）**：布局、步骤数、颜色、点击路径及可访问性目标，均不是 AD&D 原书要求，也不是已实现行为。

没有启动浏览器、拍摄截图、测量实际点击耗时、运行屏幕阅读器或执行自动化测试。下面的“难找、容易混淆”等是依据源码结构的风险判断，不是已观察到的玩家失败率。本文没有查看其他 Phase A 审查报告；共享台账是共同基础，不据此承接其他审查者的结论。

## 3. 四视图的信息架构（D）

建议路径为工作区内 `/character/create/`、`/character/sheet/`、`/character/growth/`、`/character/journal/`。这是待讨论路由合同，不是本轮新增路由。既有深链接可留作入口，进入时明确当前打开对象及其类型。

全局壳：角色选择器（姓名、职业/已授等级、战役、分支）→ 四视图导航 → 当前视图；顶栏同时显示“内存有更改 / 正在保存 / 本地已保存 / 保存冲突”和备份入口。未打开角色时显示“继续本地角色 / 打开文件 / 创建角色”，不默认打开最近一个同名旧表。

角色切换必须先处理当前未保存内容：保存成功再切换，或导出后明确放弃内存候选，或取消。现有控制器要求刷新后加载，不把“无损切换”误写成已有能力。原型可以模拟切换，真实接线是后续实现项。跨视图只是改变同一对象的投影，不重复导入、扣款、掷骰或提交行动。

| 视图 | 首要任务和首屏 | 次级区域与明确主动作 |
|---|---|---|
| create 创建 | 恢复草稿；看“当前步骤、阻塞项、下一项”。身份/方法先行，资料解释按需展开 | 五阶段：战役与属性 → 身份资格 → 开局资源 → 法术/装备等任务 → 审核准入。每阶段只有一个主要推进动作；并行任务可以任选顺序，不伪造规则依赖 |
| sheet 人物 | 一眼读取当前 HP/生命限制、AC、移动说明、已授等级和可用资源；“记录伤害 / 使用物品 / 记录施法” | 属性与豁免；武器及攻击表入口；准备副本；库存/钱包；职业能力。HP、等级等由档案派生，不能当普通输入自由覆盖 |
| growth 成长 | 当前已授等级、累计 XP、下一门槛、当前训练阶段和“现在能做什么” | 经验结算 → 候选/门槛 → 计划/付款 → 实际时间地点/冲突 → 授级 → 本次能力变化与选择。主动作随实际阶段改变，旁列阻塞原因和定位入口 |
| journal 日志 | 最近游戏活动、操作结果、时间/地点缺口；按“场次 / 类型 / 来源”过滤 | 事件详情含来源、前后变化、行动 ID、DM 标签、采用解释；训练/休养时间线与备份历史分开。主动作“查看记录”，仅在已有命令支持时提供“补记事实” |

sheet 与 growth 中的相关项目链接到 journal 对应记录，journal 的未决事项返回准确任务。规则来源打开辅助面板，关闭后保留输入和焦点；全站规则检索放于“资料”入口，避免占据玩家主要任务导航。

### 响应式与经典参考配色

沿用实际站点 `global.css:2–8,21` 的白纸、深灰墨色、暗红链接与细线，不假定存在未提供的参考截图。建议令牌：背景 `#fff`，正文 `#222`，链接/主按钮 `#6b1d1d`，次级文字 `#555`，分隔线 `#aaa`，说明底 `#f4f1eb`。标题衬线、数值与表单清晰字体；不采用大面积纹理、装饰阴影或只靠颜色表达状态。具体对比度须后续测量。

- ≥1024px：主内容加约 280px 上下文栏；create 左步骤、右当前任务；sheet 核心状态首行，任务区两列；growth 主流程与阻塞摘要并列；journal 列表与详情分栏。
- 768–1023px：两列内容在文本挤压时折为一列；规则/事件详情进抽屉，不压缩主表单。
- <768px：单列，四项任务导航置底或紧贴顶部（二选一原型试验，默认底栏）；底部安全区留空，动作条不遮最后一项。关键状态和下一步置顶；武器/库存按项目卡展示，不把整页变成宽表。
- 验收尺寸 360、390、768、1280px，另检查 320 CSS px 重排及 200% 缩放。普通任务无页面级横滚；攻击矩阵等二维资料允许有标签的局部滚动。
- 常用目标建议至少 44×44 CSS px；键盘有可见焦点，抽屉打开后聚焦标题/首字段，关闭回触发点，Escape 可关闭未提交面板；错误摘要链接字段，结果用 live region 宣告。以上为产品验收目标，不声称已完成无障碍认证。

## 4. 状态组件与 2–3 次交互合同（D）

通用状态必须分开表达：**尚未填写、已记录、需要 DM、来源待核、功能未接入、失败**；任务“已记录”与规则“核验范围”是不同轴。不要显示一个绿色“RAW 合法”总章。按钮不能只有 disabled：邻近显示原因及可达的下一步。

共同组件：角色/分支栏；保存状态条；任务卡（状态、责任人、前置、来源、去处理）；资源条（现值、单位、限制）；操作抽屉（输入、变化预览、确认、结果）；来源面板；事件行；冲突卡。操作确认后显示真实变化与保存状态，而非仅 toast。提交失败保留输入和原状态；提交中屏蔽重复提交，成功后不得重复扣同一副本或同一付款。

以下交互数从“目标角色已打开、当前视图可见”计：一次按钮激活/一组表单填写/最终确认各算一步，滚动不假装没有成本；文本录入的每个键击不单独计数。复杂规则审核不承诺三步完成。

| 常用任务 | 2–3 次交互的路径 | 约束 |
|---|---|---|
| 记录伤害 | ① sheet 点“伤害” ② 填数值，查看 HP/生命状态预览 ③ 确认 | 尚未初始化 HP 或同一击政策未定，改显示真实前置；不能跳过 DM 条件来满足步数 |
| 使用一项物资 | ① 点库存项“使用” ② 填数量/来源，预览剩余与单位 ③ 确认 | 一包/一周口粮不是一天；未知单位不得默认 1 日；需拆包时转子任务并说明额外步骤 |
| 施放已有准备副本 | ① 点具体副本 ② 填实际情境、组件裁定与效果记录 ③ 确认 | 仅消费选中副本，不自动命中、算伤害、扣组件或重新准备；受生命限制时就地阻止 |
| 查一项规则来源 | ① 点“依据” ② 选择具体来源定位 | 页码未核不能展示为已核；返回不丢失草稿 |
| 继续创建 | ① 选草稿 ② 点“继续下一项” | 恢复步骤和现有事实，不重掷骰或重建身份 |
| 检查成长阻塞 | ① growth 点阻塞卡 ② 到对应输入或 DM 说明 | “等待 DM”须有清楚责任说明；不是隐藏的一键覆盖 |
| 查看最近记录 | ① journal 点事件 ② 展开依据/变化 | 玩家投影不得含 DM 私密值、失败研究秘密等 |
| 保存/备份 | ① 点保存；或 ① 点备份 ② 选完整档/公开摘要 ③ 确认导出 | 只能列实际支持格式。公开摘要导出未接线时应明确未接入；不能把隐藏字段的完整 JSON 当公开摘要 |

“记录伤害”等现有运营行动要求 DM 标签；玩家可填待提交输入，但原型不能冒称存在远程 DM 审批、真实权限认证或多人同步。若当前档案只支持本地 DM 执行，提交按钮需写明这一点。原型模拟数据必须标为演示，不能污染真实档案。

## 5. 创建与成长依赖处理（D，受 S/E 约束）

### 创建

依赖链为：明确允许的方法 → 原骰与属性确认 → 种族/职业等资格计算 → 各开局任务 → 必需任务与裁定齐备 → 本地准入声明。HP/资金、语言、熟练、装备、初始法术在各自前置满足后并行；非施法职业显示“不适用及原因”，不能要求填假法术来完成清单。

属性、种族、职业、阵营改变可能影响 HP 骰、金钱、语言、熟练、装备许可、法术流程。改变前显示“将重新检查的任务”和原结果；取消不发生变化。对于已有锁定身份的导入进度，提供保全原件、另建候选的明确出口；新候选不能继承旧准入或把旧任务直接标完整。即使原骰可作为引用保留，是否合法沿用仍需当前路径检查。该交互是设计需求，现有 invalidate 不是安全分支实现。

已记录骰子旁显示“查看骰面”，再点击记录必须说明将替换什么，不因在界面间往返而重掷。装备调整保留实际库存单位和钱包币种；法术必须拆开“理解资格 / 实际取得的书内法术 / 准备份数”。待 DM 卡只收集对应事实和理由，不能用通用“已完成”复选框生成缺失事实。

### 成长

growth 顶部区分“已授等级”和“经验已达下一门槛”；XP 达标只产生后续任务。阶段顺序由现有状态决定，展示可读映射，不从 UI 自建等级状态机。

1. 结算：经验与实际财富是两个事实；显示场次与重复记录检查，评价仅按允许披露范围展示。
2. 候选与门槛：职业/上限等条件、待 DM 原因；不支持的多/双职业及扩展路径只读/待接入，不降格成普通单职处理。
3. 训练计划/付款：显示精确总费用和币种、钱包余额、实际交付/找零；提供合理显示单位，但不能自动把钱包币种换成虚拟 cp 再伪造找零。计划、付款、开始训练是不同事实。
4. 实际占用：记录游戏日期、时长、地点；展示时间覆盖、地点边界、重叠后果各自的缺项。旧课程对账只补事实，不增加进度、不重复扣款。
5. 完成与授级：展示 HP 原骰和实际授级时点。提交使用现行入口重新校验；按钮曾启用不代表后补活动后仍可完成。

### 10.2 对主方案的判断：可做有界试验，不能代替接线证明

采用隔离 `/character/prototype/`，用 `#create`、`#sheet`、`#growth`、`#journal` 寻址，同一内存合成角色贯穿四视图，是合理的本期边界。它能验证任务发现、信息密度、状态反馈、依赖说明及取消/失败路径；不用真实档案或数据库，避免让演示动作产生实际战役事实。代价是保存、跨页续玩、真实档案投影、权限和多年历史性能均没有得到验证。原型页必须常驻“合成演示，刷新重置；未记录真实准入或 RAW 完整认证”，不能显示生产式“本地已保存”或“已准入”成功章。

具体意见及保留条件：

1. **hash 四视图值得保留，但不是四个生产路由的验证。** 首次直达 `#growth`、浏览器前进/后退和未知 hash 均要定义；切换仅改视图，不重建角色、不应用行动。刷新后应回到相同视图及初始合成状态并解释重置，不能暗示 URL 包含可恢复角色。标题、焦点和当前导航状态随 hash 更新；生产路径整合仍待后续设计。
2. **一个合成角色应优先选普通单职业 MU，但需承认单样本偏差。** 这样 DMG 生成、资格、一级 HP/金钱、MU 起始法术和普通训练计算可以互相一致。不要让同一人物在不同视图变为战士或神术职业。起始快照可以完整预置，但 create 修改身份/属性之后，旧 HP、钱币、法术等下游必须失效并重新检查；若本期不支持安全重建，则锁定受影响身份控件并准确说明。可以改变输入查看独立计算预览，不能把预览结果伪装已应用到角色。
3. **复用计算器是支点，不是完成训练程序。** DMG 方法、资格、起始 MU 法术、金钱/HP/训练只在其既有已核范围内复用；原骰须固定在预览草案，确认不能再掷一次。训练费用算对，不等于已确认导师、付款、连续占用、地点后果和授级。若原型未接整套守卫，“应用训练”最多写入明确的合成计划事件；不得仅凭计算器成功改变已授等级。可以演示阻塞与计划变化，不能把尚未接入的复杂流程做成假完成按钮。
4. **最新一步撤销有用，但容易产生错误心智模型。** 显示为“撤销上一步演示操作”，不用“纠正角色历史”。只在最新可撤销行动与当前修订匹配时可用，不能跳过后续动作撤销较早付款。恢复整份先前合成状态及对应事件视图，不以反向治疗/退款替代。查看来源、筛选、切 hash 不消耗撤销资格；新行动使更早行动不再可撤销；撤销后重做默认不支持。生产行动继续走现有 parser/commit，不能向其移植“删最新事件即可修复”的假设。
5. **零 HP、恢复和研究的诚实空态仍需可用。** 会降至 0 或以下的伤害预览应说明零 HP 流程未支持，并在应用前阻止，HP 和事件均不变；不要截到 1 或跳过死亡/休养后继续假运营。施法副本耗尽后直接显示复杂恢复未支持，不因切日、切视图或撤销无关动作补回。研究只能生成显式“研究提案”的演示记录，不扣钱包、不占训练日历、不学会法术、不显示成功倒计时；提案费用如仅是建议值须标明不是已发生支出。
6. **原型导出有价值，但会被误当便携角色。** 使用专属 prototype envelope、明确版本及合成标记，文件名也含 prototype；它与 schema 1.1 的角色格式不混同。不接受真实创建、准入、运营、旧表或公开摘要文件；若原型不提供导入，界面直接说明只有导出，没有恢复承诺。若以后提供原型回读，只接受同类受支持 envelope，未知版本拒绝；不得据此宣称完整生产导入器已识别或拒绝所有原型文件。文件真实落盘也不能仅靠下载请求成功断言。

### 10.3 preview → atomic apply → event：必须讲清的合成语义

预览绑定当前合成修订、目标稳定 ID、已生成骰面及输入。开启/关闭预览不改角色、不追加事件；任何导致基线变化的已应用动作都使旧预览过期。确认时再次校验同一基线，先在隔离候选上完成全部计算及事件构造，再一次发布新状态和事件列表。失败保留原状态/事件和可修正输入；双击确认不得应用两次。

这里的 atomic 只承诺本页内存里的“状态与演示事件一起成功或一起失败”，不包括 IndexedDB、多标签同步或生产事务。每条事件显式区分“演示应用”“计算预览（不记账）”“研究提案（无规则效果）”；journal 不把所有条目写成现实已发生事实。撤销可保留一条不具战役效力的“演示操作已撤销”说明，也可移出活动事件列表，但设计必须选定一种，并保证 sheet/growth/journal 一致，不留下仍被统计的已撤销消费。

### 10.4 统一生产格式提案：复用 schema 1.1 有方向价值，尚无兼容结论

接受“沿用现有 schema 1.1 作为统一生产格式的提案；现有 archives 无损保留，适配器以后实现”，不建议另造第三套生产角色格式。但不能把通用 1.1 结构通过等同于当前 core-admission/core-campaign 重放通过；B 第 5 节已经列出二者是不同 format，数字/字符串版本表达也不同。

无损保留至少区分原始字节与语义事实：未经适配的旧档应作为原件保全，不能经过 JSON parse/stringify 后就宣称字节级无损；原 format、版本、未知字段、行动顺序、分支和当时检查策略也不能因映射丢失。未来适配器需提供字段/事件映射与往返夹具，说明哪些可执行、哪些只保全、哪些需人工确认。仅把旧档嵌入一个 1.1 外壳并不自动取得续玩能力，公开投影更不能升级成完整私档。

因此本期可以在设计中画出统一入口/兼容说明，不能导出看似正式的 1.1 合成角色，也不能做假迁移成功。真实生产动作继续交给已有 runtime parser/commit；将来 1.1 适配器仍须通过该边界，而不是用统一 schema 绕过旧动作只读和当前写入政策。接受该方向，保留对其实现成本和兼容性的判断，等实际映射证据再审。

### 10.5 调整本人的验收边界与本轮最小清单
