# AD&D 1E 中文规则站：全站审查汇总与改造路线

日期：2026-10-11  
范围：三轮源码、构建产物、规则原文与桌边任务审查。本文合并此前两轮报告和本轮复扫；按问题而非按审查者整理。

## 目标

网站应同时服务四种任务：创建角色、跑战斗、主持探险、核查原书。界面保持简洁、复古、少装饰，但规则来源、版本差异和下一步操作必须清楚。

核心原则：

1. 不以现代 D&D 直觉替代 1E 程序。
2. 结构化数据、教程和工具必须能回到具体规则书章节。
3. 核心、扩展、可选和战役专用内容都收录，但不得静默混用。
4. 随机结果保留骰点过程；DM 覆盖必须显式记录。
5. “能构建”不等于“翻译完成、资料完整或规则可用”。

## 当前规模与质量基线

- 653 个法术、524 个怪物、738 件物品、24 个职业、15 个种族、179 张随机表、22 本书、1382 个出版章节。
- 怪物中 211 条中文名与英文名相同，232 条中文名含拉丁字母，441 条缺页码，96 条描述少于 100 字。
- 怪物有 39 组规范化英文名重复；MM 内至少 16 组重复录入。
- 法术有 56 组规范化英文名重复，包含跨职业环级、重印、修订和真实重复等不同情况。
- 524 条怪物中 441 条无页码；653 条法术中 622 条无页码；738 件物品中 689 件无页码。

## P0：会直接产生错误规则或错误角色

### 规则包与跨书关系

- 全站没有真正的战役规则包状态，只把 PHB、DMG、UA、OA、DSG、WSG、FF、MM2、REF、DLA、GHA 等数组直接拼接。
- 核心种族资格被 UA/DLA 关系原地修改，无法恢复纯 PHB 资格视图。
- 数据无法表达 `requires`、`extends`、`replaces`、`incompatibleWith`、`setting` 和 DM 选用版本。
- UA 与 OA 都有 Barbarian，PHB 与 OA 都有 Monk，但当前只以并列条目处理。
- WSG 与 DSG 的水中战斗等规则存在直接差异，不能合并成单一结论。
- OA 不只是几个职业和种族，还依赖荣誉、家族、气、武术、个人先攻、东方装备和独立施法程序。

需要建立 `campaignProfile`，至少记录核心包、UA、OA、DSG、WSG、战役包、细分可选规则和房规。来源筛选与“规则实际生效”必须是两个概念。

### 车卡程序

- 现有“3d6”和“4d6 去最低”按钮都不是 DMG 四种方法的完整实现，还会无提示覆盖属性。
- 没有区分原始骰值、种族调整和最终值；职业资格检查可能使用错误数值。
- 一级魔法师可以自由选择任意环级法术，绕过 Read Magic 与攻击/防御/杂项随机表。
- 一级幻术师没有执行三次 d12、重复重掷等程序。
- 已知法术、法术书、今日记忆、剩余施法次数被混成四个通用栏位。
- 多职业和双职无法表达；等级字段不驱动 HP、攻击矩阵、豁免、攻击次数、法术位、盗贼能力或驱散不死生物。
- 没有随机起始金钱、采购账本、余额和战役价格调整。
- 核心与扩展装备混入；武器几乎全收，护甲却受固定中文名白名单限制。
- “没有规则冲突”只代表少量检查未报错，不代表角色完成或合法。

正确顺序：战役配置 → DMG 属性生成 → 种族/职业/阵营 → 年龄等可选随机表 → HP → 起始金钱与采购 → 熟练项和语言 → 各职业法术取得 → 攻击/豁免等派生值 → 开局检查。

### 战斗判定

- PHB“攻击与豁免矩阵”入口没有完整数值矩阵，真正数据埋在 DMG 长文中。
- 怪物攻击等级与怪物豁免等级使用不同的 HD 折算，不能共用一个解析函数。
- 施法中断缺少声明时点、攻击发生段、完成段、受击/未通过豁免、失去敏捷 AC 等关键规则。
- 接近、冲锋、撤退、武器长度、架枪迎击和冲锋间隔没有形成可执行流程。
- 多重攻击程序与“爪/爪/咬的一组攻击”容易被混为一谈。

### 怪物数据

- FF/MM2 导入器将“见下文”“可变”“不适用”等无法解析的 AC 回填为 0，可能直接制造错误战斗数据。
- 同一 MM 内重复条目字段互相冲突；同名跨书版本没有版本关系或差异提示。
- 322 条非 MM 或 slug 不一致的怪物无法获得正确原文章节链接。
- 大量字段仍为“未记载”“见下文”“原条目未单列”，却被 schema 当作完成数据。

## P1：严重妨碍桌边使用

### 信息架构与导航

- `/play/`、`/combat/`、`/rules/`、`/books/` 的职责重叠，缺少“教程/速查/专题/原书”类型标识。
- 顶部导航过平；桌边高频的攻击矩阵、豁免和随机表反而不突出。
- 面包屑主要按 URL 推断，不反映内容层级和书名。
- 详情页缺少上一个、下一个和保留筛选条件的返回路径。
- 首页按资料类型组织多于按“我现在要做什么”组织。

### 战斗、遭遇与主持

- 战斗教程是摘要目录，不是可照着执行的判定卡；缺少近战、投射、冲锋、多重攻击、盾牌、背后攻击和施法中断的完整例子。
- 豁免缺少“效果应查哪一栏”的选择帮助。
- 怪物详情不能回答攻击行、豁免行、特殊攻击触发、施法等级和本轮攻击程序。
- `/dm/` 仍是链接目录，没有遭遇、先攻、HP、状态、法术持续时间、士气和战后结算工作台。
- 遭遇、旅行、休整和随机表没有形成可保存的运行记录。

### 怪物与法术检索

- 怪物详情缺少战斗摘要、特殊能力词典和攻击矩阵入口。
- 怪物列表此前不显示来源，同名条目无法区分；筛选状态不进入 URL。
- 搜索索引遗漏怪物特殊攻击/防御、伤害、HD、魔抗、灵能等关键字段。
- 法术搜索遗漏成分、时间、距离、持续时间、范围、豁免和材料。
- `SpellSchema` 只有单一 `level`，不能表示同一法术对不同职业的不同环级和版本关系。
- 法术及职业的原文链接经常按职业或 PHB 硬映射，忽略实际来源书。

### 数据来源与覆盖

- 来源字段缺页码且 section 不验证真实章节；书籍 ID、缩写和完整书名混用。
- 22 本书的结构化覆盖极不均衡。DSG/WSG 快速规则不足，DDG/L&L 未进入信仰系统，MotP 未进入位面速查，多个设定书只能全文检索。
- 需要“书籍能力清单”：声明每本书应贡献职业、种族、法术、装备、怪物、规则、随机表中的哪些类型。

## P2：可用性与工程质量

- 筛选后用 `innerHTML` 重建的表格会丢失 `scope`；结果计数缺少 `aria-live`。
- 主导航缺 `aria-current`、跳到正文链接；视觉分隔符会被读屏朗读。
- 移动端宽表依赖横向滚动，第一列和上下文容易丢失。
- 当前 CSS 已是深红链接且默认无下划线；旧截图更可能来自旧构建、缓存或未加载样式。
- 构建未自动串联规则测试和链接检查；链接检查不验证锚点、资源、动态链接、query 语义或错误但存在的来源页。
- schema 主要检查字段类型，没有区分解析成功、资料完整、翻译完成、规则可用、规则包已启用和版本已裁定。
- 导入器可能静默截断描述，跳过计数与输入区块不守恒，也缺少幂等测试。

## 目标信息架构

- `/play/`：按场景执行的教程与流程。
- `/combat/`：攻击、豁免、先攻、AC、伤害等桌边速查。
- `/rules/`：跨书专题和版本关系。
- `/books/`：可核查的原书译文。
- `/character/`：由战役规则包驱动的车卡程序与角色记录。
- `/dm/`：遭遇、战斗、旅行和休整的主持工具。
- 怪物、法术、装备、职业、种族：结构化资料库，始终显示来源、规则包和完整度。

## 分阶段实施路线

### 阶段 A：来源和检索基础

- 所有职业、种族、法术、装备、怪物显示来源并可按来源筛选。
- 搜索类型参数真实生效；补齐每类条目的必索引字段。
- 怪物筛选写入 URL；同名结果显示来源。
- 建立规则包、战役包、可选规则和冲突关系的数据模型。

### 阶段 B：核心 1E 车卡

- DMG 四种属性生成法及完整骰点日志。
- 随机起始金钱与采购账本。
- 魔法师和幻术师起始法术随机程序；牧师/德鲁伊祈祷与准备程序。
- 单职业等级 1 的 HP、攻击矩阵、豁免和法术位。
- 完整性检查与 DM 裁定记录。

### 阶段 C：扩展车卡

- 多职业、双职和吟游诗人特殊进阶。
- UA 的容貌、骑士、野蛮人、杂技盗贼、武器专精。
- OA 的家族、荣誉、第二职业、气、武术和独立法术表。
- DLA/GHA/FR 等战役包的种族、职业、神祇、法术与装备依赖。

### 阶段 D：战斗桌边速查

- 四类角色攻击矩阵、怪物攻击矩阵、五类豁免矩阵。
- 怪物攻击 HD 与豁免等级的独立折算。
- 施法声明/开始/完成/中断时序卡。
- 接近、冲锋、撤退、迎击、多重攻击程序示例。
- 怪物“本轮怎么跑”摘要和高频特殊能力词典。

### 阶段 E：数据治理与自动化

- 修复 AC 解析失败回填 0；建立 null/variable/not-applicable 状态。
- 重复怪物和法术登记 canonical、variant、reprint、supersedes 关系。
- 翻译状态、占位符、短描述和缺来源报告设置不恶化基线。
- CI 固定执行：数据验证 → 类型检查 → 规则测试 → 构建 → 搜索覆盖 → 链接/资源/锚点检查。

## 本轮已经开始的改进

- 职业和种族列表新增来源列、来源筛选、URL 状态和结果计数。
- 快速车卡新增可见规则来源选择，并在种族/职业选项中显示来源；未启用来源会被标记。
- 规则来源配置保存到浏览器和角色 JSON；默认仅启用核心资料，并同步限制职业、种族、武器、护甲与法术选项。
- 移除了不符合 DMG 完整程序的“3d6/4d6”快捷覆盖按钮，避免继续生成看似合法但过程错误的属性。
- 怪物列表新增来源列，筛选条件保存到 URL，动态输出进行 HTML 转义。
- 全站搜索新增类型筛选、加载和失败状态；原有 `?type=spell|monster|item` 链接开始真实生效。
- 搜索索引补入怪物战斗字段、法术判定字段和装备战斗字段。
- FF/MM2 无法解析的 AC 现在保存为 `null` 并显示原始文字，不再伪装成 AC 0；AC 数值筛选会排除未知值。

这些只是规则包基础的第一步。目前的来源配置仍未表达覆盖、依赖与冲突关系，也尚未解决基础种族数据已被扩展关系原地改写的问题。

## 验收标准

- 用户可以明确选择本团启用的规则包，并知道每个选择来自哪里、依赖什么、与什么冲突。
- 一级角色不能自由取得不合法高环法术；所有随机车卡步骤可追溯。
- DM 能从角色或怪物页在两次点击内得到攻击目标、豁免类别和原书依据。
- 同名跨书条目始终显示版本；未知数据永远不会伪装成数值 0。
- 任一公开详情页可从搜索找到；任一来源链接可落到真实章节；筛选结果可分享和恢复。
