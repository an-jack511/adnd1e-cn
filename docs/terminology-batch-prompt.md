# 术语一致性接口：批处理提示词

以下正文可直接用作后续术语整理任务的 prompt。

---

你的交付目标是给 AD&D 1E 后续翻译提供可直接查询、稳定复用的中英术语接口，并统一同一语境下的译名。优先提供可用的中文主译、英文异体、旧译别名、语境和来源，不以反复核查、候选数量或证明后续版不存在译名为工作目标。

## 决策原则

1. 现有主表是唯一译名权威。先读当前批次及相关主表片段，已核定或已完成自译的条目直接复用，不重新逐词搜索。仅当出现原词识别错误、明确的新译名证据、用户指定更名或不同义项时重开，并记录触发原因。
2. 一个概念在一个语境中采用一个中文主译。旧译放入检索别名；单复数、大小写和明确拼写变体优先关联已有概念。不同义项记录 senses，必要时拆分，不按英文相同强行合并。
3. 候选必须有 1E 原文定位。只核对足以辨识词项与含义的上下文，不为定译扩展到整章规则审校。现有中文底稿是线索，不能独立充当正确性证据。
4. 批量查本地 3R→5E→5R 名称索引，精确且语义相符则按优先级采用；索引无命中不能说该版本没有译名。只对缺证据或有真实冲突的项目补充网络检索，不为每个普通词重复联网。相同后端连续两次失败后，本会话停止重试该后端，记录限制并继续。
5. 可用来源没有适用译法时，当批完成自译。沿用现有词素及 D&D 中文惯例，理由简短具体，标 adapted-variant / self-translated-after-3R-5E-5R-search。自译是可以供接口使用的项目主译，不是临时占位，也不冒称官方译名。
6. pending 只用于原词或关键语境无法辨明。风格上有几个均可接受的译法时，选最符合既有体系的一种，不来回比较。确有困难的少量项目单列，不能阻塞整批。

## 批处理步骤

1. 开始时检查工作树，保留其他任务改动；读取最近接续记录，不重读整个台账。
2. 使用 `python scripts/terminology/prepare-review-batch.py --book PHB --pages 10:14 --limit 40` 生成紧凑审阅包；页码为候选的 PDF 页码，也可用 `--terms` 指定一个子系统的英文词头清单。优先限定子系统页段，避免跨全书追着泛词与标题跑。审阅包只提供线索，不自动批准名称；队列页码可能截断，完整覆盖仍以原书扫描为准。
3. 同一原书、同一子系统每批约 30–60 个词；必要时以完整小节为边界缩小批次。对候选分流为：复用已有主译、并为别名、新增定译、排除非术语、待辨原词。普通章节标题、说明句、OCR 串词不因已有中文就入库。
4. 批量核对原文相关页段，完成主译决策；只对真实疑难项作第二遍审阅，普通项不再重复检查。把决策写入既有 rule-terms.tsv、decisions.json 或 sense-notes.json，不另造第二套译名主表。
5. 对排除项或原词问题，用稳定的英文词头、来源定位、处理结果和简短理由记入候选处理记录。下批生成时用 `--receipts` 读取该记录，避免重新审阅；仅在新语境或识别纠错时重开。无法确认的项目独立进入疑难队列。
6. 每个批次只做一次新增项结构校验：中文非空、类别和状态合法、原文来源可定位、无误造重复词头；不要逐项反复调用全库检查。
7. 小批可先积累主表决策；交接、发布或一组完整批次结束时，集中重生成目录、查词数据和 API。建库阶段不运行会遍改全站正文的 apply；全站一致性迁移另行成批执行。
8. 完整测试、构建与提交遵循既有留档节点，不因每几个词反复构建。报告实际新增／复用／排除／疑难数量和下一页段，不输出长篇过程。

## 接口可用性

- 后续翻译默认采用 verified-exact 和 adapted-variant 的中文主译；自译不因缺少外部精确译名而被排除。
- adapted-element、pending、reference-conflict 不能直接当作完整规范译名；只有部分语素已核的名称应尽快补全并确定项目主译。
- 先按英文或异体精确查词，再按类别、书系和 senses 判断语境；主译用于正文，旧译只供搜索兼容。
- 保留稳定 ID，不因更名改变链接或调用方存储的标识。
- 当前接口 `/api/terminology/v1.json` 包含完整目录及状态；调用方必须按上述规则筛选，不能把全部返回项当作已核译名。

## 接续记录

只记录：原书与已处理页段、本批有效决策数、未解决原词问题、最近生成／验证状态、下一批入口。区分有效概念数、词形数、候选数；不用候选总量宣称术语覆盖完整，也不为数量目标填充普通标题。

用户要求果断推进：证据达到上述门槛就定译并继续，已定结论默认稳定；新证据出现时允许有记录地纠正，不以绝对不会再变更为定译前提。
