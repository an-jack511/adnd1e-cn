# AD&D 1e 译名表

本目录是网站内可独立构建、受版本控制的译名主表。`npm run terminology:apply` 或 `npm run terminology:audit` 会将完整副本同步到父目录 `X:\Games\DND\1e\translation\names`，供书稿与长期整理使用。两处是同一表的主表与导出副本，不另建第二套人工口径。根目录既有 `glossary.json`、`translation/monster-names.tsv` 与 `monster-rule-terms.tsv` 已作为历史资料纳入清单；不覆盖它们已有的未提交修改。

## 文件

- `catalog.json`：只列 AD&D 1E 资料库原文词项；后续版中英文名称只作为匹配到 1E 词项后的参考，不独立创建词条。记录英文、中文、异体、类别、稳定 ID、来源位置、核实状态及出处。
- `names.tsv`：便于查看、筛选的同表导出；只保留从 1E 资料库原文确认的词项。标题候选和待核项目依状态标明，不将后续版独有名称列作词条。
- `rule-terms.tsv`：AD&D 1E 规则术语主表；由 `catalog.py --inventory` 纳入 `catalog.json`、导出表及网站查词数据。每项记录中文主译、英文词形、范围及证据；`project-glossary` 表示与本站 DMG 术语表逐项对应。无精确后续版译名时按 D&D 中文惯例自译并标注方法，不因缺少外部来源而留空。
- `references/5etools-names.json`：仅供 5E／5R 译名检索的参考库；匹配到 1E 原词后，将译名证据附在该 1E 条目上，不把此文件的词项复制进公开术语表。
- `references/huiji-names.json`：灰机检索索引中实际可见的中英文名称对。访问方式明确为搜索索引摘录；直接页面与 API 的 HTTP 403 不记作全文读取。
- `references/setting-names.json`：FR、龙枪、灰鹰的设定名称证据；灰鹰国名表另与英文原表按固定表格编号及行序对照。未筛选的标题与索引名称会在网站表中标为“设定名称索引（含标题候选）”，不得直接当作专名定译。
- `settings-entities.json`：已选定的设定专名及适用书系；仅在对应书系补充“中文（English）”，保留原英文。纯英文标题进入原文术语候选扫描；确认语义词项后先找版本译法，找不到则自译，只有原词或语境不明才保留待核。
- `decisions.json`：需人工判断的英文异体及人物语素；所有推导必须指向已读到的名称证据。
- `sense-notes.json`：同一英文词头的多义区分，记录中文义项、规则／设定语境、释义与原文定位；目录生成后同步进入开放 API 与术语查询页。
- `reports/pending.json`：仍待核实的项目暂译与章节候选。
- `reports/conflicts.json`：同优先级来源分歧或多个历史中文名称。多个旧译不必然意味着当前存在错误。
- `reports/near-matches.json`：仅供审阅的近似英文匹配；绝不因相似度自动合并。
- `reports/context-review.json`：短名称、重名旧译在正文中的保留位置。普通叙述词也会命中，需要读上下文，不能一律判为错译。
- `reports/last-application.json`、`drift.json`：最近应用记录及重新应用会产生的变化。
- `src/data/terminology/names.json`：网站使用的精简副本，保留旧译检索与人物卡兼容；由脚本生成。
- `reports/source-candidates.tsv` 与 `reports/source-candidates-priority.tsv`：从本地 OCR、PHB／DMG 全书 PDF 文本层抽取、Dragon 杂志 OCR 片段及章节 Markdown 底稿提取英文词组、单词候选和中英对照线索；优先队列依中英底稿、3R／5E／5R 名称证据、原书标题和跨页信号排序，必须逐项核对原文语境后才进入正式词库。
- `reports/rule-coverage-audit.md`：规则术语按书目与子系统的覆盖审查清单；记录当前术语表来源偏斜、原文材料和未完成的逐页盘点。规则术语条目数不是覆盖完整度。
- `scripts/terminology/mine-source-terms.py`：重建上述候选队列，不改正文或正式词条；候选保留原文语料定位，不导出 OCR 段落。除多词短语外，单词只从原书独立标题、表格标签和中英对照标题中抽取，之后仍须回到原页辨析；OCR 正文中的高频串词会被降低优先级，不能据此认定为术语。

## 全站词条规模

本词库只收录从 AD&D 1E 资料库英文原文确认的规则、法术、魔法物品、武器装备、怪物、生物、职业、子职、种族、人物／神祇、组织、地理、位面、战役设定及杂志专名。用户要求尽可能完整，不设总量上限；20,000 项是最低规模预期而非封顶或完成条件，如 1E 原文有效术语更多就继续扩充。3R、5E、5R 只用于检索并记录 1E 词项的译名，不将后续版本独有英文词项单列进词库、网站查词页或 API。每个确认为术语的 1E 原词都必须录入中文主译：先按 3R→5E→5R 找译法，无适用译法时按既有术语与 D&D 翻译惯例自译，并记录原书定位、检索范围和自译依据。同一英文在不同语境有不同含义时，按义项分别记录译名、适用语境和原书出处，不机械统一。

截至 2026-11-27，1E 原文术语目录共 8,706 项：1,419 项已核名称、6,683 项待核、481 项已注明范围的译名调整（含自译）、122 项部分语素已核、1 项来源或语境分歧。规则主表与生成目录均为 864 个英文词形，其中 500 项 verified-exact、364 项 adapted-variant，无待核项。阵营性质与阵营语言分义，装备价目中的包装数量与复合名称不算新机制。来源候选池仍为74,999个候选、32,577个优先项；数量不代表覆盖完成。最近来源、候选去向及验证见 `reports/phb-*-review.json`、对应 receipts 和 `phb-basics-equipment-validation.json`。

## 规则术语覆盖范围

规则主表不以某一页的筛选结果或单一术语类别的条数作为“已完整”的依据。维护时按主要规则书及主要拓展逐册盘点，并至少覆盖以下概念域：

1. 时间单位、回合流程、行动类型、先攻、突袭、遭遇距离与行动顺序；
2. 六项属性、属性调整、能力检定、基础成功数、熟练项检定及检定修正；
3. 护甲等级、攻击矩阵、攻击骰、命中判定、攻击次数、武器类型、伤害与伤害修正；
4. 豁免检定及各豁免类别、豁免矩阵、豁免修正、物品豁免、魔法抗性；
5. 生命骰、生命值、恢复、死亡、复生、能级吸取与状态效果；
6. 移动率、射程、作用区域、持续时间、追击与规避、负重、地形和环境行动；
7. 士气、遭遇反应、交涉、雇佣兵与随从、追逐及其他 NPC／怪物行为规则；
8. 职业等级、施法者等级、法术环级、法术环位、施法时间、成分、法术学习和魔法研究；
9. 武器与非武器熟练项、武器专精、格斗、擒抱、压制、制服性攻击及各类特殊战斗程序；
10. 灵能、财宝、经验值、奖励、装备、载具，以及各拓展书新增的专门子系统（例如水上、地下、荒野、东方战斗规则）。

灵能术语须按机制层级分别登记：`Psionic Strength`“灵能强度”、`Psionic Ability Score`“灵能能力值”、`Attack Strength`“攻击强度”、`Defense Strength`“防御强度”、`Attack Point(s)`“攻击点数”、`Defense Point(s)`“防御点数”与 `Psionic Strength Points`“灵能强度点数”不可混为一谈；`Minor Discipline`“次级学科”与 `Minor Devotion`“次级灵能技艺”、`Major Discipline`“主要学科”与 `Major Science`“主要灵能科学”也分别对应分类与具体学科类型。此处用 PHB 灵能体系作为 1E 基准，不能因后续版本术语相近便合并机制。

每个概念须结合英文原文、中文正文、表格字段和跨书引用核定；优先录入会被复用或曾出现译名漂移的规则名词，也收录对理解规则必需的近义词区分。单纯章节标题可作证据或索引，但不以堆积标题冒充规则词汇覆盖。相同英文若在不同规则书中语义或机制不同，应拆分并注明适用版本／语境；单复数、词形变化和普通叙述不自动视作独立规则术语。

“详尽”按概念和原书覆盖衡量，不按词条数量衡量。先按书目 × 概念域 × 子系统扫描原书正文、表格、附录和索引，登记已查页段和缺口。每个确认为术语的英文词项都须在建库阶段获得中文主译：先按 3R→5E→5R 查找可用的准确译法；找不到现成译法时，再根据现有术语、D&D 中文惯例、词素和原书语境自译。自译需注明 `self-translated-after-3R-5E-5R-search`、构词依据与已查来源，并使用 `adapted-variant` 区分于外部精确译名；不因站点不可访问而留空待核。只有原词识别、指称或关键语境尚不清楚时才保留 pending。依次完成核心规则书、主要规则拓展、其他 AD&D 资料和 Dragon 杂志中所有计划类别的原文扫描与候选处理；整个术语库覆盖完成后，才逐词扫描全站一致性。规则词、法术、怪物、装备和各类专名都属于第一阶段，不留到一致性核对之后再建库。章节标题只是入口，须继续扫正文、表格和实际引用，不以词条总数代替覆盖证明。

对跨书高频词，另查“同英文不同机制”“同机制不同英文”“缩写／全称”“单复数与派生语”“正文、标题、表格译名是否一致”。例如回合／轮／段、攻击骰／命中修正、熟练项／熟练项检定／熟练项栏位，分别记录，不能因词面近似而合并。最终术语表须适合未来翻译直接查用：中文主译、英文原词及必要异体、术语类别、适用语境、核对状态和可定位来源缺一不可。

近似术语必须先比较机制再借用译名。例如 UA 附录 R 的 `Subdual` 是一种有专门伤害比例与投降／俘获后果的战斗程序，本站依该 1E 双语标题译为“制服”；不能仅因 3R 资料中出现“淤伤”便机械替换，因为 3R 的“神圣淤伤”是将额外伤害转为非致命伤害的专长语境。凡新旧版机制并非一一对应，都应把它们作为不同概念记录，并以版本限定译名。

状态字段表达译名方法和证据范围：`verified-exact` 表示英文与可定位中英名称精确对应，不等于规则机制已逐句复核；`adapted-variant` 也用于无适用版本译名后按现行术语与 D&D 译法惯例完成的自译，范围字段须标 `self-translated-after-3R-5E-5R-search`。`pending` 仅用于原词、来源文本或关键语境尚未辨清，不用于“没找到现成译名”。只凭目录／索引不得声称已精确核译；但确认原文词项后仍须给出自译主译。

## 版本与采用顺序

`5R` 指第五版修订规则体系：2024《玩家手册》、2024《城主指南》、2025《怪物图鉴》及对应修订扩展。5etools 分别使用 `XPHB`、`XDMG`、`XMM`，不能把 `PHB` 的 2014 记录当作 5R。本站将修订扩展 `FRHoF`、`FRAiF`、`EFA` 明列为 5R；新增来源需先核实再扩展此表，不能只按出版年份猜版本。

`3R` 指第三版修订版，即 D&D 3.5。灰机三版站为 https://dnd3r.huijiwiki.com/；五版站为 https://dnd.huijiwiki.com/。前者的《玩家手册》与出版物导航实际标有“3R核心”。五版站的 2024 玩家手册与地下城主指南须与旧版页面区分。

译名检索按 **3R → 5E → 5R** 顺序，先找现成的精确、适用译法；找到后按优先级采用。页面/API 不可访问时如实记录并继续查后续版本，不能把访问失败说成该版本无译名。对同一语境确无适用译法时，自译为中文主译，并记录检索范围、1E 原文、词素依据和翻译惯例；自译标为 `adapted-variant`，`verificationScope` 使用 `self-translated-after-3R-5E-5R-search`。这是一项已完成的译名决策，不等于官方译名。已采用名称译法不代表导入该版本规则机制。若所列同优先级译法分歧，结合 1E 上下文与既有 D&D 译法作出项目主译，其他形式记为别名或说明，不因分歧停住词库构建。同一英文在不同规则或设定语境中出现多个义项时，逐义核对并在词库/API 语境说明中标明义项、译名和页码；拼写相同但含义不同的规则应分开记录，不能强行统一。

已存在的后续版语素推导不能覆盖精确的 3R 名称。怪物名称参考排除具名 NPC；Wolfwere、Shade 等身份或译文有疑问的记录单独挂起，不因英文同名而直接套用。未找到 3R 证据的名称不能标为“3R 已核实”。

`verified-exact` 表示名称与所列中英名称对精确对应，不表示 AD&D 1E 规则机制已逐句复核。`adapted-variant` 表示主译已确定且注明理由与范围，既包括有依据的跨版本名称采用，也包括依 3R→5E→5R 查找后仍无适用现成译名、按既有术语和 D&D 翻译惯例完成的自译；自译须在 `verificationScope` 标 `self-translated-after-3R-5E-5R-search`，不得称为官方译名。`adapted-element` 用于只核实了部分姓名或名称语素、但其余内容仍未处理的情形。`pending` 只用于原词、来源文本或关键语境尚未辨清的候选，不得仅因外部译名未找到而保留。

例如 Drawmij → 卓姆吉、Mordenkainen → 魔邓肯、Nystul → 涅斯图、Otto → 奥图均从参考法术的中文姓名语素提取，记录为语素推导；不会将未找到的灰鹰法术全名伪报成已验证。`Tenser's Floating Disc` 相对参考 `Disk` 是明确拼写异体，沿用“谭森浮碟术”。

## 维护

### 离线参考数据库优先（2026-11-26）

日常核译先查本地数据库，仍按 **3R → 5E → 5R** 排序；不逐词重复联网。只有离线资料缺项、同名异义不清或需要更新证据时再查线上。3R 的本地资料尚不完整，离线无命中不能写成“3R 没有译法”。

```powershell
# 首次下载／续传公开 JSON，并重建本地名称索引；已有快照不重复下载
npm run terminology:cache
# 中英文精确查询，全程离线
npm run terminology:lookup -- "Fireball"
# 包含查询只作人工检索线索，不自动匹配译名
npm run terminology:lookup -- "Spell" --contains --limit 20
# 重建索引，全程离线；需要主动更新下载时给 fetch 加 --refresh
python scripts/terminology/offline-references.py index
```

缓存位于 `X:\Games\DND\1e\tmp\terminology-reference-cache`：`objects/` 保留下载到的原始 JSON；`manifest.json` 记录 URL、下载时间、SHA-256、体积与失败原因；`names.sqlite3` 为本地检索库；`summary.json` 为覆盖统计。原始后续版资料仅供本地核译，不进入本站正文、发布 API 或 Git。索引只提取明确的 `ENG_name`／`name` 中英字段，保留书码、页码与 JSON 位置；正文中的普通英文不自动猜配中文。标题字段标作 `heading-reference`，不能凭名称命中直接认定是规则术语。未明确分类的书码标 `unclassified`，不按年份猜作 5R。

`prepare-review-batch.py` 自动读取该 SQLite 索引，并合并受版本控制的名称证据；离线库不参与全站自动改名。核定后仍须把选定的证据及义项写入主表／决策。HTTP 403、404、超时和缺项均明确保留；刷新失败不覆盖已有有效快照。3R 灰机 `Data:数据库目录.json` 的公开 API／raw 入口目前访问受限，现仅缓存已有 3R 名称证据，不宣称已下载该站完整数据库。

1. `npm run terminology:fetch` 刷新 5etools 名称证据；不会下载或混用后续版规则。
2. 将实际读到的灰机名称对加入 `references/huiji-names.json`，保留访问方式及日期；不得根据 URL 猜页面内容。
3. 按 3R→5E→5R 检索现成译法；无适用译法时在 `decisions.json` 记录自译主译、范围标签 `self-translated-after-3R-5E-5R-search`、词素和 D&D 中文惯例理由。把 `near-matches.json` 只当作检索线索，不能因没有精确命中而停留在待核。
4. `npm run terminology:apply` 更新清单、正文、完整 HTML 详情、标题、目录、搜索缓存、导入资料与本地导出，再生成物品索引。
5. `npm run terminology:audit` 应为零漂移；随后运行 `npm run test:terminology`、资料库/阅读器/人物卡测试、类型检查、构建和链接检查。
6. 运行 `python scripts/terminology/mine-source-terms.py` 刷新原文候选池；先审阅 priority 队列，再按中英原文、来源语境及 3R→5E→5R 对照结果提交正式主译。OCR 与自动配对只提供线索，不提升核对状态。

## 开放接口
