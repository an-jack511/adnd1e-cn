# AD&D 1e 译名表

本目录是网站内可独立构建、受版本控制的译名主表。`npm run terminology:apply` 或 `npm run terminology:audit` 会将完整副本同步到父目录 `X:\Games\DND\1e\translation\names`，供书稿与长期整理使用。两处是同一表的主表与导出副本，不另建第二套人工口径。根目录既有 `glossary.json`、`translation/monster-names.tsv` 与 `monster-rule-terms.tsv` 已作为历史资料纳入清单；不覆盖它们已有的未提交修改。

## 文件

- `catalog.json`：英文、规范中文、旧中文、英文异体、类别、稳定 ID、逐文件出现位置、核实状态、参考版本、出处及说明。
- `names.tsv`：便于查看、筛选的同表导出。章节标题和未筛选的跨版本名称均单独标注候选／参考状态，不能当作已核定的 1E 词条。
- `rule-terms.tsv`：AD&D 1E 规则术语主表；由 `catalog.py --inventory` 纳入 `catalog.json`、导出表及网站查词数据。每项记录核对状态和具体证据位置；`project-glossary` 表示已与本站 DMG 术语表逐项对应，不等同于已按 3R 外部译名来源核实。待核项不得当作定译使用。
- `references/5etools-names.json`：只存公开参考数据的名称对、书目代码、页码、数据 URL、条目 URL、访问日期和数据摘要；不引入后续版本规则正文。
- `references/huiji-names.json`：灰机检索索引中实际可见的中英文名称对。访问方式明确为搜索索引摘录；直接页面与 API 的 HTTP 403 不记作全文读取。
- `references/setting-names.json`：FR、龙枪、灰鹰的设定名称证据；灰鹰国名表另与英文原表按固定表格编号及行序对照。未筛选的标题与索引名称会在网站表中标为“设定名称索引（含标题候选）”，不得直接当作专名定译。
- `settings-entities.json`：已选定的设定专名及适用书系；仅在对应书系补充“中文（English）”，保留原英文。纯英文标题也进入待核清单。
- `decisions.json`：需人工判断的英文异体及人物语素；所有推导必须指向已读到的名称证据。
- `reports/pending.json`：仍待核实的项目暂译与章节候选。
- `reports/conflicts.json`：同优先级来源分歧或多个历史中文名称。多个旧译不必然意味着当前存在错误。
- `reports/near-matches.json`：仅供审阅的近似英文匹配；绝不因相似度自动合并。
- `reports/context-review.json`：短名称、重名旧译在正文中的保留位置。普通叙述词也会命中，需要读上下文，不能一律判为错译。
- `reports/last-application.json`、`drift.json`：最近应用记录及重新应用会产生的变化。
- `src/data/terminology/names.json`：网站使用的精简副本，保留旧译检索与人物卡兼容；由脚本生成。
- `reports/source-candidates.tsv` 与 `reports/source-candidates-priority.tsv`：从本地 OCR、Dragon 杂志 OCR 片段及章节 Markdown 底稿提取的英文候选和中英对照线索；必须复核后才进入正式词库。
- `scripts/terminology/mine-source-terms.py`：重建上述候选队列，不改正文或正式词条；候选保留原文语料定位，不导出 OCR 段落。

## 全站词条规模

本词库覆盖规则、法术、魔法物品、武器装备、怪物、生物、职业、子职、种族、人物／神祇、组织、地理、位面、战役设定及杂志新增专名。用户要求尽可能完整，参考总规模至少 20,000 项（如来源确有这么多）；标题候选、历史译名及后续版本参考必须与已校准的 AD&D 1E 词条分开统计。核对顺序按 3R → 5E → 5R；缺少对应来源时保留待核状态，并记录 1E 原书定位。

截至 2026-11-25，网站术语表共 22,095 条：其中 555 条为从中文翻译底稿筛出的中英并列候选，逐条保留底稿位置并标为待核；另排除 23 条把作者署名误配为人名译文的候选。当前状态统计为 1,381 条名称已核、6,140 条待核、6 条语境或来源分歧、33 条已注明范围的译名调整、122 条仅核实部分语素，以及 14,413 条跨版本参考。DMG 两份术语表提供 263 条中英名称出处；这些出处只证明名称对照，不等于对应规则机制已审完。后续版本参考不作为 1E 定译，设定索引含章节标题候选；总数不是已核术语或独立概念数，须按原书语境继续去重、校准。规则术语主表现有 501 项。

## 规则术语覆盖范围

规则主表不以某一页的筛选结果或单一术语类别的条数作为“已完整”的依据。维护时按主要规则书及主要拓展逐册盘点，并至少覆盖以下概念域：

1. 时间单位、回合流程、行动类型、先攻、突袭、遭遇距离与行动顺序；
2. 六项属性、属性调整、能力检定、基础成功数、熟练项检定及检定修正；
3. 护甲等级、攻击矩阵、攻击骰、命中判定、攻击次数、武器类型、伤害与伤害修正；
4. 豁免检定及各豁免类别、豁免矩阵、豁免修正、物品豁免、魔法抗性；
5. 生命骰、生命值、恢复、死亡、复生、能级吸取与状态效果；
6. 移动率、射程、作用区域、持续时间、追击与规避、负重、地形和环境行动；
7. 士气、遭遇反应、交涉、雇佣兵与随从、追逐及其他 NPC／怪物行为规则；
8. 职业等级、施法者等级、法术环级、法术环位、施法时间、成分、法术学习和魔法研究；
9. 武器与非武器熟练项、武器专精、格斗、擒抱、压制、制服性攻击及各类特殊战斗程序；
10. 灵能、财宝、经验值、奖励、装备、载具，以及各拓展书新增的专门子系统（例如水上、地下、荒野、东方战斗规则）。

灵能术语须按机制层级分别登记：`Psionic Strength`“灵能强度”、`Psionic Ability Score`“灵能能力值”、`Attack Strength`“攻击强度”、`Defense Strength`“防御强度”、`Attack Point(s)`“攻击点数”、`Defense Point(s)`“防御点数”与 `Psionic Strength Points`“灵能强度点数”不可混为一谈；`Minor Discipline`“次级学科”与 `Minor Devotion`“次级灵能技艺”、`Major Discipline`“主要学科”与 `Major Science`“主要灵能科学”也分别对应分类与具体学科类型。此处用 PHB 灵能体系作为 1E 基准，不能因后续版本术语相近便合并机制。

每个概念须结合英文原文、中文正文、表格字段和跨书引用核定；优先录入会被复用或曾出现译名漂移的规则名词，也收录对理解规则必需的近义词区分。单纯章节标题可作证据或索引，但不以堆积标题冒充规则词汇覆盖。相同英文若在不同规则书中语义或机制不同，应拆分并注明适用版本／语境；单复数、词形变化和普通叙述不自动视作独立规则术语。

“详尽”按概念和用法覆盖衡量，不按词条数量衡量。逐册审查时建立“书目 × 概念域 × 子系统”的覆盖记录：明确已逐项查过的正文、表格、附录和索引，标出尚未检查的页段；每个候选概念再与主表比对，记录已收录、需合并为异体、语境不同须拆分、或证据不足待核。核心规则书（PHB、DMG、MM）及主要规则拓展（UA、WSG、DSG、OA）完成后，再扩展至其他规则资料。章节标题只作入口，必须进一步查看正文定义、表格列名和实际引用，防止遗漏散落在段落或表格里的规则名词。不要用当前主表条目数或术语页单次筛选数推断工作已完成。

对跨书高频词，另查“同英文不同机制”“同机制不同英文”“缩写／全称”“单复数与派生语”“正文、标题、表格译名是否一致”。例如回合／轮／段、攻击骰／命中修正、熟练项／熟练项检定／熟练项栏位，分别记录，不能因词面近似而合并。最终术语表须适合未来翻译直接查用：中文主译、英文原词及必要异体、术语类别、适用语境、核对状态和可定位来源缺一不可。

近似术语必须先比较机制再借用译名。例如 UA 附录 R 的 `Subdual` 是一种有专门伤害比例与投降／俘获后果的战斗程序，本站依该 1E 双语标题译为“制服”；不能仅因 3R 资料中出现“淤伤”便机械替换，因为 3R 的“神圣淤伤”是将额外伤害转为非致命伤害的专长语境。凡新旧版机制并非一一对应，都应把它们作为不同概念记录，并以版本限定译名。

状态字段只表达证据范围：`verified-exact` 可表示与本站 1E 双语标题或术语释义逐字核对，不等于整条机制已经完成规则审计；凡仅凭目录、搜索索引、推测译法或尚未查看上下文的条目，必须保持待核。逐册盘点时同步登记已覆盖的概念域、待补子域和证据来源，避免只因主表条数增长便宣称详尽。

## 版本与采用顺序

`5R` 指第五版修订规则体系：2024《玩家手册》、2024《城主指南》、2025《怪物图鉴》及对应修订扩展。5etools 分别使用 `XPHB`、`XDMG`、`XMM`，不能把 `PHB` 的 2014 记录当作 5R。本站将修订扩展 `FRHoF`、`FRAiF`、`EFA` 明列为 5R；新增来源需先核实再扩展此表，不能只按出版年份猜版本。

`3R` 指第三版修订版，即 D&D 3.5。灰机三版站为 https://dnd3r.huijiwiki.com/；五版站为 https://dnd.huijiwiki.com/。前者的《玩家手册》与出版物导航实际标有“3R核心”。五版站的 2024 玩家手册与地下城主指南须与旧版页面区分。

按用户最新偏好，名称优先级为 **3R → 5E → 5R**。目录匹配到这些版本的英文精确名称时，自动采用优先级最高者；普通本地译名决策只作兜底，只有明确标记的 `userOverride` 才可覆盖匹配到的版本证据。3R 没有可核对名称时才采用后续版证据。同优先级译名有分歧时挂起，不以出现次数投票。每条证据保留版本差异；不会因英文相同而导入或合并机制。

已存在的后续版语素推导不能覆盖精确的 3R 名称。怪物名称参考排除具名 NPC；Wolfwere、Shade 等身份或译文有疑问的记录单独挂起，不因英文同名而直接套用。未找到 3R 证据的名称不能标为“3R 已核实”。

`verified-exact` 表示该名称的英文与公开中英名称对精确对应（只正规化大小写、空白、弯引号和横线），不表示该词条的 1e 规则已经由人逐句复核。`adapted-variant` 是已记录理由的少量标点、分词、词形与单复数调整。`adapted-element` 通常只核实了施法者姓名语素，`verificationScope` 明确标明完整名称其余部分仍待核。`pending` 保留项目暂译，不能宣称通行或官方译名。

例如 Drawmij → 卓姆吉、Mordenkainen → 魔邓肯、Nystul → 涅斯图、Otto → 奥图均从参考法术的中文姓名语素提取，记录为语素推导；不会将未找到的灰鹰法术全名伪报成已验证。`Tenser's Floating Disc` 相对参考 `Disk` 是明确拼写异体，沿用“谭森浮碟术”。

## 维护

1. `npm run terminology:fetch` 刷新 5etools 名称证据；不会下载或混用后续版规则。
2. 将实际读到的灰机名称对加入 `references/huiji-names.json`，保留访问方式及日期；不得根据 URL 猜页面内容。
3. 审阅 `near-matches.json` 与待核清单；需要调整语素时在 `decisions.json` 写清范围和理由。
4. `npm run terminology:apply` 更新清单、正文、完整 HTML 详情、标题、目录、搜索缓存、导入资料与本地导出，再生成物品索引。
5. `npm run terminology:audit` 应为零漂移；随后运行 `npm run test:terminology`、资料库/阅读器/人物卡测试、类型检查、构建和链接检查。
6. 运行 `python scripts/terminology/mine-source-terms.py` 刷新原文候选池；先审阅 priority 队列，再按中英原文、来源语境及 3R→5E→5R 对照结果提交正式主译。OCR 与自动配对只提供线索，不提升核对状态。

## 开放接口

- 完整 JSON：`/api/terminology/v1.json`，无需密钥，允许跨域读取；字段含稳定 ID、中英文主名、类别、核对状态、适用范围、旧译与英文异体、版本来源、资料库出现位置及校准备注。
- OpenAPI 3.1 说明：`/api/terminology/openapi-v1.json`。
- 旧地址 `/translation-table.json` 继续保留，供现有客户端兼容；新接入请使用带版本号的 API。
- 这是静态目录快照。调用方可按中英文、别名、类别和状态筛选；`reference-only`、`pending`、`adapted-element` 与 `reference-conflict` 均不可当成已核定的 AD&D 1E 译名。
- API 会随站点版本更新；完整目录允许 AI 翻译工具下载后本地检索，不需要密钥或账号。

应用按完整英文标签处理重名与短名称，其他仅应用无歧义的已核准中文替换；当前规范名受保护。重复运行须收敛。原英文、稳定 ID、链接与来源字段不改。装备旧代码按中文合并示例的逻辑已改用明确的历史 ID 对照，避免改名影响旧人物卡。已有手写人物卡备注不自动改写。

引用说明若带有完整英文名称，页面会按主表显示对应的新中文名；底层原始出处字段仍保留原文。没有英文对照的出处说明不猜测替换。

`import:library` 与 `import:regional` 在整理完成后自动应用主表；正常构建用 Node 检查所有实际资料库名称，发现新词条缺表或已确认名称回退时失败。构建只依赖网站仓库中的受跟踪文件，不依赖父目录副本或联网访问。

这是一份持续扩充的全站清单与核实队列，绝不声称所有候选都已经人工核实。

Ranger 按用户最终选择采用 3R 译名“巡林客”，条目注明“注：在一些规则中，也译为游侠。”，游侠保留为旧译检索别名。
